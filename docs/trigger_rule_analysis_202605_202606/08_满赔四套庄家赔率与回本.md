## 2. 0/27 是中奖回本，不是市场作废

0 是小、27 是大。彩28网盘 / 满赔2.0 的大小单双：**押中** 0 或 27 才退本；押错全亏。

| 场景 | 彩28网盘 / 满赔2.0 大小单双 | 满赔3.2 | 满赔2.8 / 旧高赔 |
|---|---|---|---|
| 开 0，买大（未中） | **miss，全亏** | miss | miss（除非另有中奖回本条款命中） |
| 开 0，买小（中） | **退本** | 若含球 0/9 → 退本；否则 hit | 豹子则退本；否则 hit |
| 开 13，买小（中） | 彩28网盘：hit；2.0：hit，注>2001 降赔 1.98 | 退本 | 退本 |
| 开 13，买小单（中） | 彩28网盘：hit；2.0：**退本** | 退本 | 退本 |
| 对子且中奖 | hit | hit | 退本 |
| 890 且中奖 | 不当顺子，按点数结算 | 当顺子，但 3.2 不单独退顺子；若含 0/9 则退本 | 当顺子并退本 |

3.2 **没有** 0/27 这条：开 0 买大是 miss；只有中奖且 ABC 含 0 或 9 才退本。

2.0 大小单双在 13/14 上是 **hit 降赔**，不是 refund，避免倍投走 `refund_action`。

## 4. 配置落点

赔率挂在结算策略上，**不**挂 `delivery_targets`。群组差异靠：订阅 `play_filter` + 路由 `play_filter` / `settlement_mode=override`。

```text
订阅 strategy.settlement_policy ──┐
                                 ├─ dispatch 冻结 snapshot（rule + overrides + catalog 赔率）
路由 settlement_policy（override）─┘
                                 ▼
开奖 → resolve_pc28_result_for_signal(冻结 rule)
                                 ▼
hit → stake × (effective_odds − 1)；refund/miss 维持现有账本
```

形状：

```python
{
  "rule_source": "follow_signal" | "subscription_fixed",
  "settlement_rule_id": "pc28_fullpay_2_8_regular",  # 固定规则时必填
  "fallback_profit_ratio": 1.0,
  "odds_overrides": {  # 可缺省；follow_signal 保存后不会出现此键
    "big_small": 2.84,
    "odd_even": 2.84,
    "combo": {"小单": 6.79, "大双": 6.79, "大单": 6.33, "小双": 6.33},
  },
}
```

- 订阅默认一套；自动触发某条路由要换庄家时，设 `settlement_mode=override`
- inherit 路由继续用订阅策略，不受其它路由 overlay 影响
- 下单后改 catalog 或改订阅，已冻结事件的盈亏不变
- `LEGACY_TO_SETTLEMENT_RULE_ID` 只含旧四条。来源信号即使写了 `pc28_fullpay_2_8` 也不会自动跟成满赔2.8
