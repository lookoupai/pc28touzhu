# 双组与杀组

组合从大单、大双、小单、小双中下注一个；双组同时下注两个；杀组排除一个，下注其余三个。每笔子注都按组合规则结算。

## 使用

1. 跟单方案选择含组合预测的来源，在“跟单玩法”中选择自选玩法，点击“只玩双组”或“只玩杀组”，也可以只选具体方向。
2. 选择均注、跟随来源金额、倍投或过关。前三种金额按**每个组合**计算：填 10 元，双组总额 20 元，杀组总额 30 元。过关选择“所选玩法过关”，再选双组或杀组；起始注为**整期总额**，等分为整数子注，尾差留仓。旧七三分注结构仍保持原来的两个下注内容，不能同时叠加组玩法。
3. 选择对应的组合结算规则及群组。双组、杀组逐注使用现有组合消息模板，整组只发一条，例如 `大单10 小双10` 或 `大单10 大双10 小单10`。
4. 自动触发可选双组/杀组的近 20/50/100 期命中率、连中连挂、开奖连续条件及路由固定玩法。Bot 使用 `/play <订阅ID> 双组` 或 `/play <订阅ID> 杀组`。

“原有全部玩法”保留原来的范围，不包含双组、杀组。旧 Bot `/play <订阅ID> 全部` 也保留原有含义。现有方案不会因升级自动加注新玩法。

双组能表达六种不同搭配，当前来源由普通组合派生的结果只有两种；其余搭配需要来源直接提供结构化信号。

| 原组合预测 | 双组下注 | 杀组排除 | 杀组下注 |
| --- | --- | --- | --- |
| 大单 | 大单＋小双 | 小双 | 大单＋大双＋小单 |
| 大双 | 大双＋小单 | 小单 | 大单＋大双＋小双 |
| 小单 | 大双＋小单 | 大双 | 大单＋小单＋小双 |
| 小双 | 大单＋小双 | 大单 | 大双＋小单＋小双 |

## 结算与统计

- 每组是一条资金事件，内含 2/3 个组合子注；每个投递目标接收一条完整消息。金额、集合、赔率与规则在派单时冻结。
- 总返还为各笔返还之和，整组净收益为总返还减总投注。倍投按整组盈利/亏损/持平推进一次；止盈止损也按整组净收益判断。
- 预测覆盖命中独立保存。命中率、预测连中连挂、日报计数按组统计，不把杀组的一中两挂计成三单。
- 命中子注退本时，其余未中子注仍亏损。例如满赔 2.0，杀小双、三组各 10，开 13：小单退本，大单和大双各亏 10；预测命中，整组亏 20，倍投进入下一手。
- 执行记录展示口令、每组合金额、总额、预测命中、每笔结果和整组净收益。人工结算必须输入和值或三球开奖，不能只点“命中/未中”估算利润。
- 重试只针对原下注窗口内明确发送失败且事件仍待发送的整组。已发送、结果未知、过期或已结束事件不能通过重试增加下注；原封盘时间不会延长。

## 来源接口与兼容

来源普通导出 URL 可以保持不变。投注端在新收到的 combo 记录上生成双组/杀组候选信号，只有已选择这些玩法的方案会消费。已解析的历史 raw item 不回填、不回放出单。

需要来源直接返回新玩法时使用：

```text
GET /api/export/predictors/<id>/signals?view=execution&include_group_plays=1
```

默认 `include_group_plays=0`，执行信号仍为原有类型。来源 `/performance` 已增加两类指标；收益模拟可选择两类新玩法并按真实多注金额计算。

双组方向使用稳定排序（大单、大双、小单、小双）和 `+` 连接，例如 `double_group:大单+小双`；杀组方向是排除项，例如 `kill_group:小双`。旧“单组”“双组”作为兼容输入，界面展示具体组合。

```json
{
  "bet_type": "kill_group",
  "bet_value": "小双",
  "confidence": null,
  "normalized_payload": {
    "selected_combos": ["大单", "大双", "小单"],
    "excluded_combo": "小双",
    "group_derivation": "opposite_combo_v1",
    "origin_combo": "大单",
    "unit_count": 3,
    "source_hints": {
      "settlement": {"settlement_rule_id": "pc28_fullpay_2_0_regular"}
    }
  }
}
```

新玩法置信度不直接沿用单组合置信度。旧 combo 导出保留原 profit_rule_id 映射，另带 `group_settlement_rule_id` 给本地派生玩法使用，避免将满赔 2.0 等新规则映射成旧网盘规则。用户固定结算规则优先于来源提示。

同一批数据内显式组信号优先于本地派生；同源同一期每种组玩法只保留一个方向。重复信号复用原信号，不新增投注；冲突的显式组信号拒绝入库。旧 combo 后续修订不改变已冻结组信号，也不阻断原 combo 的兼容处理。

第三方原生双组/杀组分类的采集尚未扩展；本次支持已有组合预测的派生导出，以及投注端接收符合上述协议的显式组信号。

## 发布说明

启用新方案前应更新两项目，投注端 API、来源同步、自动触发、结算进程需全部加载新代码。初始化会增加可空 `prediction_hit` 字段和查询索引，并升级日报触发器；旧事件的预测命中字段为 NULL，保持原统计口径，不重算历史资金。

本次同时修正来源高赔 ABC 模拟的大小单双/组合退本规则，与投注端既有规则一致；重新运行该规则的收益模拟会采用修正后的口径，已落账资金及派单时冻结的旧快照不受影响。

本次未操作生产数据库、重启服务或启用实际投注方案。回滚代码前应先停用新玩法并完成其在途结算；旧版不识别组级事件。
