# 定时时段前的有效信号

## 使用

自动规则的定时设置增加“允许使用时段开始前发布的有效信号”，默认关闭，旧规则保持原口径。支持“定时”和“条件＋定时”，适用于均注、倍投及过关。

开启后，只放宽“信号发布时间必须晚于时段开始”这一个条件。仍须满足：当前处于允许时段、信号未超过最大延迟、目标期尚未开奖、开奖时钟可靠，以及开奖前有足够投递余量（项目默认 40 秒）。次数、冷却、风控、归属和在途限制继续生效。

信号在 23:59:50 发布、00:00:14 到达，目标期在 00:02:30 开奖时，00:00 开始的规则可以使用该信号。旧口径会因发布时间早于零点而跳过。

配置以 `schedule.allow_pre_window_signal` 布尔值保存。编辑不重置原轮次、已用次数或历史账本。新页面连接旧后端时，开启该设置的保存请求会被阻止并提示重启，避免静默丢失配置。

## 与模拟端对齐

AITradingSimulator 的过关设置新增“按定时规则回放”。填写相同的时段、星期、最大延迟、开奖前投递余量、每时段及每天轮数，勾选相同的“允许时段前信号”选项。需要时可加入额外同步／检查延迟，并设置结束后等待时的冷却期数。

新轮受时段限制；本轮已经开始后可跨时段、跨午夜继续，直到达标或资金不足。定时回放按北京时间自然日和启动时段计次；“立即续开”跳过触发冷却，但不绕过时段和次数上限。

回放使用模拟项目保存的预测创建时间和外部抓取时间，估算信号可用于下注的时刻。外部信号的新鲜度以外部抓取时间计算，与导出信号的发布时间口径一致；必须等到预测实际写入之后才可使用。它不包含跟单端真实轮询、网络延迟、送达回执或历史条件指标，不等于逐次执行日志重演。设置额外延迟可以对比同步时差的影响。

使用当时相同的杀组、链条滚动、起始 10、目标 3 关及彩28满赔2.8规则，在临时数据库与模拟端输入同一时间线：

| 选项 | 起始期号 | 投注总额序列 | 单期净盈亏 | 最终余额 |

| 关闭 | 3504913 | 9、18、39 | +11.37、+22.74、−39 | 5.11 |

两端逐期下注金额、净盈亏、余额和关数一致。可复验：

```sh
PYTHONPATH=src python3 tests/check_schedule_signal_parity.py --simulator-src /www/wwwroot/AITradingSimulator
```

脚本仅创建临时执行数据库，使用固定历史样本，不访问生产账本或调用消息发送器。

## 生效

需要分别重启跟单项目相关进程和 AITradingSimulator，再刷新页面。生产规则须明确勾选新选项后保存；本次开发未自动改动生产规则，也不会将已结束轮次改记为成功或补发历史投注。
