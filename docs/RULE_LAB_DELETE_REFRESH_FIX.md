# 删除残留与自动刷新修复

2026-11-28：原批次8“遗漏回补 V1 · 组合长连错 · 2026年10—11月 · 新赔率”的删除任务10在10:55:13 UTC后停于1000/1198行，批次处于deleting，已经清掉部分成绩。此次处理继续执行用户原删除请求，不重建该实验。

生产数据库外置副本在普通进程能清完剩余198行，在与生产相同的ProtectSystem=strict服务限制下复现disk I/O error。服务没有可写系统临时目录，SQLite删除实验定义时需要临时语句日志，整页因此回滚。将SQLITE_TMPDIR指向既有可写实验目录后，同一副本在相同限制下处理198行并完成，未增加系统可写范围。原错误还被误标为空间不足，现区分读写失败并将重试原因持久化到删除任务。

页面原来每15秒自动更新，未保护select焦点，每次重建批次选项且读取期间禁用选择。现在30秒自动更新、5秒任务轮询，操作select时暂停；已发出的后台响应也不能打断新选择，列表内容不变时复用选项节点。删除中的对象立即退出普通选择列表，任务进度仍可从系统面板查看。

验证使用临时真实SQLite/WSGI和Chromium，覆盖删除失败页回滚、错误记录/恢复、受限服务临时日志、下拉框焦点、读取中开始选择、旧响应晚到、任务完成时用户正在选择、删除后立即隐藏，以及原管理/研究/模板/报告/续算流程。未对其他实验执行删改，也未创建新自动计划。
