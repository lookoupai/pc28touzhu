# 保存与启动分离

## 使用流程

新建或复制跟单方案只保存配置，状态为“未启动”。保存后选择：

- **配置自动规则**：跳转时自动选中刚保存的方案；规则也先保存为未启用。核对时段、条件、金额、关数、结算来源后，点击“启用规则并让方案待命”。如果当前条件和时段已经满足，后续调度可能立即触发。
- **开始直接跟单**：从启动后新入库的来源信号开始直接跟单。再次点击启动不会改变信号边界；暂停后重新启动会跳过暂停期间的已有信号。

编辑方案或规则只更新配置，保留启用状态；保存日风控调整也不会自动解除当天的停止，需要使用“恢复规则日风控”。草稿不会预先创建过关周期，首次发单使用最后保存的金额和关数。已运行过关轮次及在途投注继续使用原快照。

自动模式触发后始终保持自动待命，均注、倍投、过关都不会切换为直接跟单。均注和倍投在未配置显式路由时使用方案投递目标的独立路由。要新增直接跟单，可复制一个未启动方案再单独启动。

## 状态与结算

方案列表分别显示启动方式、当前状态、关联规则和正在运行的自动过关轮次。

- “等待时间窗口／条件”与“今日已收工”分开：结束一轮后等待条件，不等于当天收工。
- “方案默认结算”和“自动规则结算配置”分开：规则可继承方案，也可通过路由覆盖；运行中过关轮次显示本轮结算快照。
- 启用规则在同一事务中核对归属、方案范围和手动在途单，再设置关联方案为自动待命并启用规则。任何一步失败都整体回滚。
- 暂停不修改已发出的投注金额或结算快照，在途结果仍可结算。有直接跟单待发送／待结算投注时不能切换自动模式。

## 数据与接口

`user_subscriptions` 增加 `launch_mode` 和 `direct_after_signal_id`。旧方案默认 `legacy`，保留原运行行为；明确选择启动方式后才转换。新方案使用 `unstarted`，直接启动后为 `direct`，自动待命为 `automatic`。

`POST /api/platform/subscriptions` 和 `POST /api/platform/auto-trigger-rules` 忽略提交的启用状态，始终创建未启动／未启用配置；编辑接口保留当前状态。状态变更必须使用各自的 `/{id}/status` 接口。

订阅列表和摘要返回 `launch_workflow: explicit_start_v1`。新页面连接未更新的后端时会阻止保存和启动请求并提示重启，避免旧后端把保存解释为启动；暂停入口仍可用。

新草稿即使被“全部方案”规则覆盖也不会自行启动。已有规则、资金账本和结算记录不会因字段迁移而重写。
