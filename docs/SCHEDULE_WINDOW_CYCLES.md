# 过关的每日与时段启动次数

## 设置

次数限制与轮次结束动作分别设置：

| 设置 | 范围与含义 |
| --- | --- |
| 每个方案每天最多启动 | 1–1000 轮，所有时段合计 |
| 每个方案每个时段最多启动 | 0–1000 轮，默认 1；0 表示不限，仍受每日上限约束 |
| 成功后／资金不足后 | 等待再次触发、下一可投注期直接续开、当天收工 |

计数范围是“规则＋方案＋北京时间启动日＋时段 ID”。同一轮向多个群组投递仍只计一轮；不同规则和不同方案分别计数。仅定时、条件加定时的自动过关使用时段额度；纯条件模式不受时段额度影响，普通均注、倍投沿用现有调度方式。

你的测试规则可设置：每日最多 3 轮，每时段最多 1 轮，成功和资金不足后均选择“等待下一个可用时段”，时段为 08:01–08:59、14:01–14:59、20:01–20:59。当天每个时段最多开一轮，不补跑错过的时段。存在可用信号且上一轮已结束时才能启动，因此这是上限，不保证每天一定跑满三轮。

每时段设为 2 时，同一时段可以开两轮。选择“等待再次触发”会重新检查条件和冷却；选择“直接续开”跳过开始条件和触发冷却，但仍受时段、每日上限、待结算和风控限制。时段次数用完时保留等待状态，在下一个仍有额度的时段继续检查，不会绕过上限。

## 一轮何时结束

某期净亏损只清零连续盈利关数。如果本轮滚仓资金仍足以投注，继续使用剩余资金尝试过关，不补入起始资金，不新建轮次，也不多计一次启动。回本不增加或清零关数。

只有达到目标关数，或本轮资金不足以继续下注，才按“成功后／资金不足后”的设置处理。时段只限制新轮的启动；已经运行的轮次可跨越时段结束时间，直到本轮完成。开始下一轮才重新使用方案的起始投注金额。

## 实现与兼容

`cycle_policy.max_starts_per_window` 保存每时段上限，不增加数据库表或列。缺少该字段的独立轮次规则默认每时段 1 轮；要恢复过去同一时段内反复开轮的行为，可明确设为 0。兼容模式沿用每时段一轮。

时段用量来自已持久化的 `auto_trigger_rule_runs`，同时识别普通时段 ID 和 `roll:序号:时段ID`，不依赖内存缓存。保存、暂停再启用、重新连接或重启不会清空已用次数。编辑原时段的起止时间保留其 ID，因此不重置用量；删除再新增时段会建立新的时段身份，仍受每日上限约束。

检查时段余量、领取日额度、创建轮次及首期派单共用写事务。无信号或派单事务回滚不占额度；显式关闭“启动时立即派单”仍沿用原有行为，成功启动一个待信号轮次即占一次。并发检查不能同时绕过上限。

页面展示各时段已用次数，记录中明确提示“当前时段启动次数已用完”。新页面遇到不支持该字段的旧后端会阻止保存，提示重启服务，避免设置被静默忽略。

新代码生效需要重启跟单项目相关服务。本次开发不修改生产规则或账本，不自动重启，也不发送测试消息。
