# PC28 投注内容与资金策略解耦

## 目标

大小、单双、单组合、号码、双组、杀组均可选择均注、倍投或过关。跟随预测、固定买某个方向、只接收某方向必须有明确区别。旧单双＋组合七三分注作为兼容结构保留，旧配置和在途事件不自动转换。

## 核心契约

- 单玩法过关新增 `structure=single_play`，配置 `play_type`、`selection_mode=follow|fixed|filter`、`fixed_value`。旧 A/B/C/D/follow_signal 含义保持。
- 一套过关方案选择一种玩法；不同玩法创建独立方案，资金、轮次和关数使用既有订阅／自动规则／路由隔离键。页面不允许在同一条资金链里悄悄切换玩法。
- 关数按本期整体净盈亏推进：盈利加一、亏损清零、持平保持。预测命中独立统计；组命中但整组亏损不能加关。
- 起始金额为一整期总风险金额。单注向下取整；双组、杀组先均分再向下取整，每个子注至少 1，未下注的尾差保留在账户。链条下一期注额为本期返还；全仓使用账户余额。
- 双组／杀组沿用一条整组事件和一条完整消息，冻结选项与等额子注；不拆成多个资金周期。单注也只建一个事件。旧七三结构保持原来的两笔账、一次合并发送。
- 已有待结算计划继续按冻结策略结算；用户切换玩法不能覆盖在途资金与状态。自动规则的重开、结束、每日上限继续沿用既有隔离机制。

## 两项目一致性

来源收益模拟沿用同样投注内容、整数金额及实际赔率结算。普通模式和过关模式共享玩法／方向选择，关数自定义；原七三结构放入兼容选项。正式运行不跨目录导入另一项目，测试使用同一组输入对照。

## 使用示例

投注端新建方案，选择“过关滚仓”及“所选玩法过关”，再选择玩法、方向和目标关数：

| 示例 | 玩法 | 方向 | 关数 |
| --- | --- | --- | --- |
| 大小过三关 | 大小 | 跟随来源预测 | 3 |
| 固定大过三关 | 大小 | 固定买大 | 3 |
| 只跟大过三关 | 大小 | 只跟大 | 3 |
| 杀组过五关 | 杀组 | 跟随来源预测或固定杀某组合 | 5 |
| 双组过十关 | 双组 | 跟随来源预测或固定两个组合 | 10 |

例如杀组起始 100：每组合 33，总下注 99，余 1 留仓。若开出的命中子注只退本金，另两注亏损，整期亏 66，关数清零；预测覆盖命中仍独立记录。

固定方向也需要所选玩法当期的来源信号作为派单时点，不凭空生成期号。来源模拟可用已有预测期号回放固定方向，但不能保证实际源每期都会输出该玩法信号。自动规则可以用其他指标触发，派单会查找同一期的实际下注玩法信号。

多个玩法使用同一来源分别建方案，各方案分别设置金额与关数。此版不在单一方案内混合多种玩法的资金；自动路由／规则的原有资金隔离仍然有效。保存修改不会重算当前轮；需等本轮结束并重开，或使用既有重开功能加载新配置，有在途单时不能抹掉旧资金。

本次同时补齐号码的开奖判定、赔率映射及冻结快照，均注／倍投的号码结算也可使用；没有新增数据库字段或自动修改现有方案。

## 验证

单注／号码／组玩法的派单、冻结结算、退款、资金守恒、关数、重复派单、并发隔离、自动触发、旧方案回归；来源 API 与页面、跨项目纯函数金额对照。只在临时数据库发送模拟回执，不操作实际投注。

跨项目测试 `AITradingSimulator/tests/check_generic_roll_parity.py` 覆盖六种玩法、八个赔率档、两种滚动方式、全部 1,000 种三球开奖和金额边界，共 96,384 个场景，返还、盈亏、余额、关数全部一致。

验证记录：投注端全量 753 项通过；来源端全量 320 项通过，随后补充的通用选择 API／方向组合测试通过；两边 Chromium 创建、切换、公开权限、手机布局检查通过。投注端新玩法选择模块覆盖率 95%。所有结算／发送流程使用临时数据库与模拟回执。

## 发布

完成验证后需重启来源项目，以及投注端平台、触发、派单／同步、结算相关进程，使它们统一加载新策略类型。未在本次开发过程中重启生产或创建实际投注方案。新玩法开始使用后，回退旧代码前需结束新玩法在途轮次，旧版不理解 `single_play`。
