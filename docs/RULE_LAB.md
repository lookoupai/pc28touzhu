# 轻量规则实验室

管理员登录后从导航打开“规则实验室”，地址为 `/rule-lab`。现有服务器入口是 `https://tg.dca.de5.net/rule-lab`。实验只做模拟记账，不创建执行任务、不发送投注消息；不同管理员只能查看自己的批次。

## 使用方式

后台状态区的“运行速度”可切换**省资源（最多0.2核）**与**加速（最多1核）**。核数是相对单CPU的计算额度，非整机百分比；默认省资源，两档内存上限均256MiB、禁swap。加速主要放宽CPU限速，不增加同时运行或保存的策略版本数，不并行启动同组全部风控方案。实际耗时由数据、磁盘及主机负载决定，不能保证固定倍数。

这是全服务设置，所有管理员实验共享。切换不重启模拟进程、不重置已有进度；页面核对实际限额后显示生效档位，服务或服务器重启后保留选择。空闲时不会因为选择加速就占满一核，也不会自动启动新实验。暂时无法核对时禁用切换，原计算继续；响应丢失时只读取实际状态，避免盲目重复提交。

速度一致性验证中发现旧版按轮历史回放有时间预算边界问题：上一笔到期结算未执行便耗尽本轮预算时，下一期可能被错误推进而漏入场。新版在同一期断点恢复，新建历史批次保存回放算法版本2。已有旧版按轮成绩原样保留，页面标记“需复核”，比较组暂停显示相对差异；该标记只基于旧算法和实际处理记录，不表示已确认每一笔都受影响，也不自动覆盖或重跑。新旧算法结果不能直接用于断言风控方案优劣。

1. 选择公开的 PC28 预测器、大小／单双／组合、固定每注金额，以及“实时模拟”或“历史回放”。历史日期按北京时间计算，最多 90 天。
2. 保存批次。大小或单双生成 25 个条件、50 个实验版本；组合使用综合条件 v2，生成 46 个条件、92 个实验版本。每个条件都包含以下两种结算预设：

   | 预设 | 大小／单双 | 小单／大双 | 大单／小双 | 退本 |
   | --- | ---: | ---: | ---: | --- |
   | OK 游戏网盘 `pc28_netdisk_regular` | 1.998 | 3.71 | 4.32 | 无特殊退本；13/14正常赔付 |
   | OK 游戏高赔常规 `pc28_high_regular` | 2.846 | 6.78 | 6.33 | 命中遇 13／14、对子、顺子（含环绕）或豹子退本；未中全亏 |

   组合玩法另可选择“组合长连错 · 7～30期”：无条件基准＋预测连错≥7、8、9、10、11、12、13、14、15、20、25、30，共13条件、26版本。综合条件 v2 已包含长连错包的所有条件，选择综合包即可同批比较其他触发条件；长连错包用于只看连错门槛。旧基础 v1 的冻结条件保留，已有批次不会自动追加或更换条件。这里的次数是开轮门槛，≥7也覆盖连错超过7期，不代表最多统计7次。预测连错与实盘连续亏损是不同指标，连错较长本身不保证下一期更容易命中。

   2026-11-27按用户提供的当前赔率表更正OK网盘常规目录：旧1.98／3.60／4.20改为1.998／3.71／4.32。用户给定适用注额为大小/单双1～1000、组合1～500，本次更正赔率和展示，不扩展到未提供的ABC、特码或其他盘。系统原有模拟金额范围未在本次新增限额校验，使用时应在提供的注额范围内。旧冻结实验/投注快照与盈亏不改写；旧网盘结果标注旧赔率，详情及CSV显示该实验冻结值。修改新目录不会重新计算旧成绩；赔率改变会影响风控停轮路径，不能只把旧中奖利润补差额。

3. 新批次保存后为**暂停**，点击启动才开始模拟。全服务最多同时运行 100 个实验版本、保存 1000 个版本；额度由所有管理员共享。暂停会释放运行额度，保留成绩；已冻结的待结算记录保留，连续回放按模拟时钟推进结算。
4. 对照同一条件两套规则的实赔、退本、亏损、净收益、ROI、最大回撤及样本量。无条件跟随是基准。ROI 为净收益除以累计投注额，不是每轮本金收益率。
5. 点击实验查看累计表现、最近90个有记录日的汇总和完整展示范围内的月度结果；可导出当前批次的汇总 CSV。存在运行或排队任务时，页面每15秒自动读取进度和成绩；隐藏页面、编辑输入或查看实验结果时暂停页面更新，后台仍继续计算。自动更新只读取结果，不会启动模拟。

页面默认先显示结果。通过顶部批次／比较组选择框切换对象，“实验结果”和“风控对比”标签每次只显示一张列表；新建和系统资源从页头按钮打开。比较组每次运行一个子方案，方案进度和管理入口保留在“比较操作与方案筛选”中。所有方案完成且输入一致前，相对基准差异为空；完成后在比较行的详情中查看累计Δ净利、ΔROI和Δ回撤。

列表提供“概览／月度／风险”三个本地视图，切换不重新请求数据。概览只保留条件与赔率、观察状态、最低月ROI、最高月日结回撤和窗口净利五列；窗口净利排序也按当前观察窗口计算。月度视图展开各月ROI或日结回撤，风险视图集中查看回撤持续、去除最佳三天净利和窗口近期表现。来源、窗口日期、原注额和共同输入提示放在表上方。

点选条件或行空白打开右侧详情抽屉；手机上铺满屏幕。关闭、Escape或遮罩返回原标签、视图、页码和筛选结果，不切换底层对象。比较组详情使用被点选子方案的真实风控和注额，因此金额换算不会误用另一个批次的配置。抽屉打开时背景不可操作并暂停自动刷新；提交中的修改不会被Escape丢弃。

## 列表观察规则

实验结果和风控比较列表共用“列表观察规则”。默认观察最近2个连续自然月（包含未完整月），要求每月投注收益率≥3%、每月≥200笔结算、每月≥10个投注日。可选择2／3／6个月或输入1～12，另可设置月收益率差距、月日结回撤注数、窗口内回撤持续天数上限；空白是不限制，0是上限为0。这些是可调整的观察门槛，不是稳定盈利认证。

完整月模式只取截止日期之前已经完整结束的连续月份，不跳过缺月或无交易月。例如截至11月27日选择2个完整月，观察9、10月；只有10月历史时显示1/2个月不足，不能改用10、11月凑足。包含11月部分数据即使通过所有门槛也只标“阶段达标”。输入缺档、冲突、旧算法需复核、窗口待结算、日账不一致或比较组尚不可比时优先显示“数据待核对”。已知暖机或晚到等跳过单独提示，不自动把所有旧数据判为无效。

概览显示最低月ROI和最高月日结回撤；月度视图显示各月ROI或日结回撤，风险视图显示窗口末14天与前14天ROI。完整门槛、样本要求和可选上限从“调整条件”抽屉查看。两段14天均以当前观察窗口截止日计算；覆盖不足时明确显示，不移到较早区间。收益和可选风险要求分开显示，月间差较大不自动等于方案较差。门槛判断使用原始整数分，显示为3.00%的2.995%不会误通过3%要求。

风险视图展示所选窗口内去除最佳三个盈利日后的净利、最长回撤持续和当前未恢复天数；它们基于日结记录，最差日可在详情月报查看。窗口之前的高点未纳入时明确提示，因此不能当作完整历史恢复时间。累计逐笔回撤和最长连亏仍是原始全区间指标，不与月日结口径混称。原轮状态、统计日、该日／本轮盈亏与停止原因保留在详情的“运行信息”展开项。

观察设置仅保存在当前浏览器，不修改实验、风控或自动续算，也不会创建新回测。完整月达标可选红／蓝／紫色高亮，阶段达标固定橙色，历史或样本不足为灰色；所有状态都同时写明文字。可仅看符合规则，并按最低月ROI、月间差距或月回撤注数排序。窗口或月份口径变更一次读取当前批次／比较组，其余阈值和颜色本地重绘；失败时保留并注明之前的显示口径。

观察字段随显式GET返回：`/batches/{id}?observation_months=2&observation_partial=true` 与 `/studies/{id}?observation_months=2&observation_partial=true`。参数必须成对，月份1～12且partial为true/false；旧无参数接口保持原形状。读取只用现存日汇总，不查询预测来源、不修改账本。详情页的金额估算不会反向影响列表原始成绩或门槛判断。

## 回测报告与月度表现

批次表或比较表点选条件打开该实验版本的详情抽屉。按北京时间自然月显示结算数、投注额、净收益、加权ROI、盈利/亏损/投注日、最差日和月内日终回撤，支持CSV导出。月度金额取自长期保留的日汇总，全部月份不以原“最近90个有记录日”裁剪；最多展示最近120个自然月，并明确范围。图形展示最近最多24个月，表格和CSV包含完整展示范围。

完整月仅指回放已跨过整个月份且配置范围涵盖该月，不证明原始预测/开奖无缺漏；存在跳过或输入冲突会显示提醒。中途开始、正在回放、截止在月内、待结算或零结算月份不计入盈利月份占比，零结算也不计为持平。连续亏损月遇到未完整或无样本月时中断。10月1日至11月26日的固定回测，11月是部分月份；启用续算并完成11月余下区间后，才可能成为完整月。当前样本不足6个完整月时提示观察不足；6个月也不是稳定性或收益保证的门槛。

报告使用常见中文回测指标：累计净利润、累计投注额、投注收益率、最大回撤金额（逐笔）、已结算笔数、胜率（实赔÷实赔与全亏笔数，退款不计）、最长连续亏损笔数、收益回撤比（净利润÷逐笔最大回撤；零回撤时为空）。月度摘要使用月度胜率、盈利/亏损月份、最长连续亏损月数及最佳/最差月份净利润。月表中的回撤从月初0净利开始按日结算计算，不能替代累计逐笔回撤。

详情顶部可调整**展示每注金额**，默认原回测金额；同比换算已有收益及止盈止损金额，属于金额估算。“资金表现”的可选输入**初始资金**默认不预填，不随展示注额自动调整。填写后以初始资金加展示口径的每日累计净利润绘制资金曲线，展示期末资金、累计收益率、最大回撤率（日结）、最低日终资金。累计收益率的分母是初始资金，投注收益率的分母是累计投注额，两者不可混称。日结最大回撤率逐日按当时的资金高点计算，例如100→200→150为25%，不是50%。日结口径可能漏掉日内回撤，不能拿它与逐笔金额硬换算。

初始资金只用于换算已有回测结果，没有模拟余额不足停投或并发占款。日终资金曾小于等于0时明确提示，停止展示收益率/回撤率，保留历史曲线和余额供诊断；历史日记录缺失或展示窗口截断时不计算完整资金表现。零结算不显示资金指标；有结算且零回撤可以正常展示0%回撤。已撤掉“历史回撤压力倍数”“可承受本金回撤”“按比例折算本金”等自定义情景项，报告不反推最低本金。

这些字段只在浏览器内计算，不会改变模拟或真实投注配置。每行互斥实验独立分析，不能把390个版本相加当作投资组合。金额估算假设止盈止损同步同比调整；若改变风控比例、触发条件、熔断或冷却期，须复制新版本实际回测。未单独建模费用、同时占款或策略相关性；没有可靠资金与日收益假设时不填充年化收益、夏普比率等数值。术语调研来源与计算边界见`.boss/rule-lab-report-terminology/research.md`。

月度数据随现有实验详情GET返回；GET不创建月报或修改账本。实验统计、日汇总和月表使用同一SQLite只读快照，worker并发写入不会产生跨时点混合结果。启用增量续算后，完成段时保存每月当前有效结果；迟到结算更新相应月份，页面不再保留旧报告版本浏览。

本版采用**固定金额、单腿、逐期跟随**。不模拟倍投、多腿或过三关，不能把这里的实赔比例当作过关率。实验启动后配置和赔率保持冻结；修改来源、金额或条件可从“管理实验”选择“修改并新建版本”。金额按已有生产结算函数逐注保留两位，再用整数分累计；例如 1 元按高赔 2.846 实赔时净利记 1.85 元，赔率本身不会先改成 2.85。

“管理实验”支持改名、编辑未启动的暂停批次、修改并新建版本及删除。原地编辑重新生成版本，退出当前自动排队并保持暂停，需要手动启动；已经运行的实验只能建立成绩从零开始的新暂停批次，原成绩保留。新版本使用当前所选模板和赔率目录；仅同比换算金额可在详情修改“展示每注金额”，无需创建新版本。比较组子方案从“管理比较组”统一管理；原批次仍被比较组引用时，删除预览会列出需要先处理的比较组。输入完整名称确认后，立即停止该对象的计算、采集及续算，后台分批删除；未结算模拟记录直接移除，不计为输赢。其他实验需要的共享输入保留，实际删除的版本释放保存额度，不自动删除其他实验腾位。请求响应未知时可只读核对并用原请求标识重试。

后台状态区的“存储占用与空间回收”显示目录、数据库、WAL日志、内部可复用页及预计可回收页；可复用页不等于磁盘已释放。删除后自动排队回收，也可手动提交空间回收任务，进度显示实际文件变化量；遇到读写占用会等待。新库自动支持分批回收，旧库需在维护窗口用 `scripts/maintenance/prepare_rule_lab_storage.py` 备份并一次转换；读取页面不会触发全库整理。管理信息按schema v5增量加入，原实验及计算进度保留。

## 按轮模拟与风控

新建表单默认按轮模拟，需明确设置至少一项启用的单轮或日止盈、止损、最多下注退出条件。阈值0表示不限；关闭某层表示该层所有阈值不生效。仅“每日最多开轮”不会结束当前轮，因此不能单独作为退出条件。可以明确选择旧逐期条件模式作为无按轮风控对照。

按轮模式仅在开轮时判断条件；轮内继续跟随所选来源的同玩法，每期固定注额，直到单轮或日风控停止。两套OK结算各自维护独立轮和日状态，退本差异可能使两者不同时间收工。最后一注可以超过止盈/止损线，收益按完整实际结算保留，不按阈值裁剪。已冻结的待结算单不会因暂停或风控而撤销。

“复制现有规则风控”按规则、路由、订阅、玩法逐项列出，不自动选择第一条。只支持可映射的固定单腿方案，不能把过关或多腿当固定单注。选择只复制风控数值，**不改变当前实验来源、触发条件、每注金额或两套OK赔率**。金额、关闭开关、按玩法覆盖及路由继承按当前配置解析，复制后保存快照，不随真实规则后续修改而变化。模拟每个实验独立使用这些数值，不复现真实规则多订阅共用的资金账户。

例如复制规则6对应路由/方案时：单轮止盈10、止损10；日止盈20、止损20；至少20笔实赔或全亏后，实赔命中率低于25%则当日停止；距上次开轮至少10期。原规则未规定的最多下注/开轮为0不限。命中率是实赔÷（实赔＋全亏），退款不入分母；等于阈值不触发。冷却从**上次开轮期号**计算，不是收工后等待10期。

规则级日风险始终独立；路由关闭日风险不会取消规则级保护，路由override与规则保护不同则保留为两套独立日门控。明确cycle日开轮上限独立于旧日金额开关：复制该上限不会重新启用已关闭但保存着的止盈值。

日状态按北京时间日期持久化。目标日下注额度在决策时按预计开奖日预占，结算后按实际开奖日记入投注数和净利，原预占随pending结束释放。延期跨午夜不会撤销已冻结下注；日开轮数仍归首次开轮时的预计目标日。晚到旧日结果只更新旧日行，不回拨新日状态。轮可以跨日延续；当日风控触发就结束当前轮并保持该日停止，次日重新等待条件。每日最多开轮只限制下一轮，不打断当前轮。

结果中的“统计日”是最近处理日，历史回放时不等于真实今天。历史区间结束仍在运行的轮标为未完结，不强制结算或截断利润。无有效投注轮单列，不能当作盈利或平局成功。

尚未启动且无模拟记录的暂停批次可点击“配置风控”；API为 `POST /api/platform/rule-lab/batches/{id}/risk-policy`，请求 `{"risk_policy":完整风控对象}`。一旦启动，即使马上暂停也不能改口径，应新建批次。风控修改与启动、worker推进在同一模拟库事务中复核，避免并发绕过限制。

轮累计指标长期保留；当前活动轮和仍有待结算依赖的日风险状态用于继续计算。闭轮更新累计完成轮、盈亏轮和止盈止损次数后移除，不再显示最近轮次列表。清理不减少累计指标，管理删除与结果保留维护共享每tick最多500行额度，不增加新定时任务。

模拟库由schema v1增量升级到v2，只增加风险列与模拟表；旧批次默认legacy逐期判断，旧金额、日汇总、游标和pending不变。发布时先停止旧模拟worker再备份、迁移和启动新版，真实业务库无需迁移。**v2模拟库不能直接交旧v1程序运行**；回退代码需停模拟服务并保留当前库，不能覆盖新产生的成绩。

## 风控参数比较与队列

在一个独立的历史回放、按轮风控批次中点击“比较风控方案”，先预览新版本数与全服务已保存/剩余容量。比较组复制全新的基准和候选，不复用原批次成绩，原来源、注额、日期、条件和两套OK冻结结算完全保留。

保留五个原候选：完整原风控、单轮止盈减半、单轮止损减半、主日层止损减半、关闭所有日层命中率熔断。止盈止损候选一次只改一项金额；对应开关已关闭/阈值0或减半不足0.01时显示不可用原因。金额按整数分减半向下取整；日止损只改主日层，附加日保护保持。

新增熔断参数对照：大小/单双为25%／20单、25%／50单、50%／20单、50%／50单；组合为20%／20单、25%／20单、30%／20单。参数同时作用于所有启用的日层，其他风控、条件、赔率与注额保持；不会打开原本关闭的日风控层。回本不计入命中率或最低样本数。与基准完全相同的参数自动去重；因此25%／20单基准通常生成大小/单双8方案、组合7方案。默认风控及现有成绩不会因模板更新而改变。

保存上限为1000版本，以容纳扩展后的参数组；同时运行上限仍为100，内存和磁盘预算保持。整组生成在一个事务中完成，容量不足不创建半组。网页为一次创建保留请求标识，网络响应未知时同名称/来源重试仍返回原组，不重复占用容量。

新组默认暂停。点击“启动比较队列”后才排队；全服务100运行版本不变，同组一次最多一个子方案，额度被其他单批次占用时等待。每完成一个子方案会排到队尾，让先等待的其他比较组获得机会。组暂停同时暂停其运行子批次，新决策停止，已冻结pending仍按原模拟时钟处理；子批次不能单独启动或编辑。子方案报错/资源暂停时整个组停止续开，不跳过失败方案偷偷比较剩余成绩。完成组不可重置成绩。

只有历史回放支持该队列；无限期的前向模拟不能轮流运行各组后把不同时段当同样本比较。历史筛选后可以另建明确的前向观察批次。

共同截止在首次实际调度时冻结，此后新增开奖不进入后排方案。固定截止本身不证明输入相同：每个方案还保存暖机及逐期实际输入、时间门控、缺失/冲突和计算特征的顺序指纹，排除本次观察时间。所有方案完成、实际覆盖与指纹一致且有历史输入，才显示同条件同OK下的Δ净利、ΔROI百分点及Δ回撤。源预测被修订、输入已清理、共享缓存冲突或覆盖差异均会显示不可比，不评冠军；后排暖机因晚写记录挤占原100期时可能不足，也会通过指纹/覆盖差异拒绝比较。

页面显示实际已处理期数和已完成方案数，不承诺完成时间或未经验证的百分比。各行是互斥模拟，不能将其利润相加称实际利润。最差日、盈利日/有投注日按实际有金额投注的日汇总计算；样本0的行不显示相对收益增益。CSV包含风控快照、共同截止、输入指纹、可比标记及差值，可追溯到原子批次和逐期/轮明细。

本次schema v2→v3只新增lab_studies与lab_study_batches等独立组关系，无上游/业务主库迁移。旧批次和已保存成绩不变；发布需停止旧lab worker并备份独立库后升级，新组由用户明确启动。CPU、内存、磁盘与清理预算不增加。

## 历史可见性

历史回放仅使用仍存在的逐期数据，按开奖前 40 秒的决策时点检查预测发布时间、历史开奖可见时间和历史预测结算时间。源库不是不可变版本档案，因此历史结果始终标为回顾性模拟，不冒充真正前瞻。缺期、缺三球、不完整窗口或过晚预测会跳过并计原因。

按轮回放还维护模拟时钟：每个历史决策点只释放当时已经公布的待结算结果；尚未公布时保持pending，不提前使用其盈亏停轮或继续下注。暂停与重启不会把模拟时钟跳到现实现在。普通固定回测在区间内不再产生新决策后清算剩余已公布结果。增量续算的段末保存可继续推进的时钟前沿和pending，不能用现实时间提前结算后再退回下一段较早的决策点；轮次可跨段、跨日保留。

实时模拟先记录 worker 实际观察到的下一期待开奖预测和条件，再用随后公布的三球结算；开奖后还会复核决策至少早于开奖 40 秒。停机、暂停或资源不足期间错过的期数不会补造为实时投注。后来的预测方向修订不取消已冻结的决策；开奖三球冲突会保留待结算状态并报错，等待核对。

恢复历史批次时，若必需输入已清理且源也不能提供，会报 `input_expired`；需新建有数据覆盖的区间，不能把缺失数据当作零命中。源撤销共享或停用后停止新决策；公开权限仅接受已启用、共享逐期记录的 `records`／`analysis` 预测器。

## 资源与数据保留

> 结果型存储：长期保存配置、累计成绩及日/月结果；已结算逐笔和已结束轮次不再保留。输入与恢复状态仅按当前计算依赖保留。既有冗余在后台分批整理，完成状态和实际空间以存储面板为准。设计边界见[结果存储修订方案](RULE_LAB_RESULT_STORAGE_DESIGN_20261127.html)。

所有实验共用精简开奖和预测记录。源库以 `mode=ro` 和短连接读取，单页最多 200 行、查询超时约 250ms；不复制大段提示词、模型响应或整库。单 worker 每次约 2 秒工作预算，实时采集间隔至少 15 秒，历史回放在间隙分批推进。

| 资源 | 限制与含义 |
| --- | --- |
| CPU | 省资源 `CPUQuota=20%`（0.2核）；加速 `CPUQuota=100%`（1核），管理员页面实时切换 |
| 内存 | `MemoryHigh=192M`、`MemoryMax=256M`、`MemorySwapMax=0`；超限可能终止 worker，重启后从事务检查点继续 |
| 进程／优先级 | 单实例文件锁，`TasksMax=16`、`Nice=10`、空闲 I/O 优先级 |
| 网络 | worker 私有网络命名空间，仅允许 Unix socket；不加载生产 `.env` 或读取投注账本 |
| 文件写入 | 放开 `data/rule_lab` 以及源目录供 SQLite 管理 WAL／SHM；源数据库主文件单独只读挂载，连接同时为 `mode=ro`／`query_only`；投注端代码只读、两项目 `.env` 对 worker 不可见 |
| 存储预算 | 模拟目录 1GiB 应用预算，含 DB／WAL／SHM 和目录内临时文件；新增计算在预算软阈值前停止增长，为采集、未结算与整理留出余量；页面按实际门禁显示 |
| 日志 | 状态变化才输出，并由 journal 每分钟最多 20 条限速；系统 journal 不包含在模拟目录的 1GiB 中 |

1GiB 是应用预算，**不是文件系统硬配额**；既有共享磁盘、系统日志和手工放入的备份不受 SQLite 页数限制。不要将备份长期堆在模拟目录。磁盘不足时先保留已有成绩与暂停原因；SQLite 删除释放的页可复用，文件通常不会立即缩小。本功能不自动运行 `VACUUM`。

- 配置、累计成绩、防重水位和每日汇总长期保留；每日汇总目前没有自动 365 天删除或月合并。
- 已结算／已跳过记录在累计成绩、日账、风控和去重水位成功提交的同一事务中移除；不再按30天或最近50笔保留。收益归属日仍按历史开奖北京时间，旧结果不重算。
- 待结算记录一直保留到实际结算或明确删除实验。共享输入只保护当前暖机、待结算对应期、暂停/排队/运行回放及连续系列尚未消费的区间；来源相同的实验共享输入。已消费且无任何依赖的输入可清理，不再保存90天缓存或两年历史副本。
- worker 每tick先给维护有界预算；管理删除与保留维护共享最多500行，物理回收每步最多256个空闲页，持久游标支持重启继续。资源暂停仍可清理；忙时等待，不在API请求里同步清空全库。
- 清理不减少累计收益、逐笔最大回撤、最长连亏和日汇总。页面展示结果及当前待结算数，不提供历史逐笔、已闭轮和旧月报版本查询。新条件或新金额只可重测实际仍可读取且覆盖已核对的输入范围。

## 部署配置

复用服务器现有 systemd 和 Python launcher，无新增依赖、无上游修改、无生产主库迁移。以下命令仅在功能版本已合入生产目录并通过 QA 后执行。现有 `pc28-python.sh` 会选择项目虚拟环境并设置 `PYTHONPATH=src`。

worker 的两个路径由 unit 明确设置，网页不能传路径：

| 变量 | 默认部署值 |
| --- | --- |
| `RULE_LAB_DATA_DIR` | `/www/wwwroot/pc28touzhu/data/rule_lab` |
| `RULE_LAB_SOURCE_DB` | `/www/wwwroot/AITradingSimulator/pc28_predictor.db` |
| `PYTHONDONTWRITEBYTECODE` | `1`，只读代码目录不生成字节码 |

平台 API 默认使用同一模拟目录；若改路径，平台服务的环境与 worker unit、读写白名单必须一起调整，不能只改 worker。数据库用 `www` 用户创建，目录建议 `0750`，文件由 worker `UMask=0077` 创建。部署前只核对并调整本次新增/修改代码与静态资源的读取权限，**不要递归改变整个项目、`.env`、会话或账本权限**。

```bash
sudo install -d -o www -g www -m 0750 /www/wwwroot/pc28touzhu/data/rule_lab
sudo install -m 0644 /www/wwwroot/pc28touzhu/deploy/systemd/pc28touzhu-rule-lab.service /etc/systemd/system/pc28touzhu-rule-lab.service
sudo systemd-analyze verify /etc/systemd/system/pc28touzhu-rule-lab.service
sudo systemctl daemon-reload
sudo systemctl enable --now pc28touzhu-rule-lab.service
sudo systemctl restart pc28touzhu-platform.service
```

只主动重启平台 API 加载新页面/接口；现有执行器、自动触发、结算和来源同步服务不需要手动重启。现有执行器可能在平台短暂不可用时退出并由 systemd 自动恢复，发布后必须检查其心跳和恢复状态，不能保证所有旧服务 PID 不变。启动新 worker 只创建空模拟库，不生成实验、不启用实盘规则。无须新增 timer、开放端口、改变 Nginx 或 DNS。

源库当前采用 WAL，上游最后一个连接关闭时可能删除 `-wal`／`-shm`。即使连接指定 `mode=ro`，SQLite 在这两个文件不存在时仍需要创建同步辅助文件；把整个源目录只读挂载会导致间歇性“无法打开数据库”。因此部署允许源目录写入，同时对 `pc28_predictor.db` 主文件设置单独只读挂载，并继续使用 `mode=ro`／`query_only`。应用只通过 SQLite 管理辅助文件，不执行源库业务写入。

这是明确的权限取舍：systemd 没有把源目录写入权限精确限制为两个文件名，服务用户仍可能写入源目录中其他未单独保护的文件；两项目 `.env` 已屏蔽。不能宣称“只有模拟目录可写”。不要将某一时刻的 WAL／SHM 单文件绑定挂载，因为上游删除重建后会换 inode；也不能使用 `immutable=1` 或 `nolock=1` 跳过活库一致性。若上游维护会替换数据库主文件 inode，维护后应重启模拟 worker，使只读绑定指向新文件。

### 多种触发条件与金额估算

“投注玩法”和“触发条件”是两个选择。每个批次选择大小、单双或组合中的一种玩法；选择“综合条件 v2（多种触发）”可在同一批次比较无条件基准、预测连错/连中、连续开出/不出、窗口命中率。组合综合包为46条件×2套赔率=92版本，其中预测连错门槛为7、8、9、10、11、12、13、14、15、20、25、30（不含3～6）；“组合长连错”专门比较7～30期的12个门槛与基准，共26版本。不同实验分别记账，不能把它们的利润相加当作同一套策略。

生成批次时，“每注模拟金额”决定实际模拟下注额。所有数值框的加减步长为1，金额仍可手动填写最多两位小数（有效范围沿用后端校验）。

实验详情顶部的**展示每注金额**可以直接换算已有成绩。例如原来每注1元，改为10元，净利润、投注额、日/月成绩、回撤金额及资金曲线按10倍展示；笔数、胜率、投注收益率、冷却期和其他次数门槛不变。单轮、每日、附加日保护的止盈止损金额同步同比换算；初始资金保持用户填写的值，例如每注10、初始资金1000时，每注占本金1%。

这只是当前详情的**金额估算**，不生成新实验、不排队、不读取历史输入、不修改数据库成绩。每次从原始成绩换算，恢复原金额或重新打开详情即可恢复原报告。月度CSV使用当前展示口径，额外导出 `amount_basis`（`original` / `estimate`）、`original_stake_amount`、`display_stake_amount`；估算文件名带 `-estimate`。批次总览CSV仍是原始成绩。

金额按分舍入，估算不重新判断逐笔结算和风控临界点，实际重测可能不同。例如赔率1.998时，1元中奖净利按分计为1元，10元中奖净利为9.98元。调整条件、止盈止损比例、熔断、冷却等行为时，在“管理 → 复制新版本”修改配置并启动实际模拟。原有精确金额重测API保留兼容，页面不再用它执行金额换算。

### 历史截止日期与后续数据

普通历史批次仍只处理创建时选定的起止日期。页面刷新只读取成绩，不延长区间。完成后可在“增量续算”中接入连续系列，原实验ID、条件、赔率、每注金额、累计收益和风控状态保留；每次追加新增一个计算段，不再生成一套策略版本，也不重复占用保存版本额度。

### 增量续算

1. 打开独立历史批次或比较组的“增量续算”，核对实际已计算期号、下一期和检查结果。旧引擎需复核、输入冲突、暖机缺失等情况会阻止接管。已有历史成绩作为迁移审计基线保留，不伪称旧回测已经拥有不可变输入证明。
2. 开启“保留后续数据”保存尚未消费的输入。采集与计算分开：仅采集时原成绩不增加；同来源的多个实验共享输入。首次接入保存必要暖机和续算边界，不再把原回放全区间重新复制为长期档案。
3. “立即追加”指定新的结束日期。单次最多追加90天，累计区间可以更长。缺少所需档案时保留等待请求；输入齐全后固定本段版本和截止再运行。同一请求重试不重复建段，页面响应丢失后通过只读预览找回回执。
4. “自动续算”默认关闭；开启后按北京时间每日指定时刻（默认00:10）追加已结束日期，停机后按不超过90天的分片追赶。手动追加不打开自动开关。关闭自动续算不取消已接受的手动段；“暂停本段计算”使用原暂停按钮，仍可继续采集后续数据。
5. 查看已计算、已采集、已结算水位，以及累计结果、简要计算段和当前月份结果。原批次日期是初始区间，累计报告使用系列有效区间。当天手动追到最新已采集期号只表示部分日进度，不能称整个自然日或自然月完成。

比较组必须整组续算，子批次不能单独追加。每段固定共同输入和截止，沿用最多100个运行版本的队列；不同进度的子方案不能直接做相对差值。净利、投注额和计数可按段对账，累计最大回撤等状态不能把分段值相加。

连续模式的暖机、目标预测、待结算开奖和输入证据都从本地冻结档案读取。上游已删除但此前已采集的输入仍可用；未采集就被清理的区间会显示缺档，不能把它当作当时没有预测。来源停用或撤销逐期共享后停止新采集与计算，已有成绩可读，关闭开关仍可操作。

月份报告分别返回 `time_complete`、`pending_count`、`coverage_quality` 和 `comparable`。完整时间范围必须有已处理边界和覆盖证明；有已知缺预测/晚预测时继续显示质量说明，不宣称输入无缺失。已算金额和质量说明保留；实际迟到结算更新该月份的当前结果，不保留所有旧显示版本。

输入按计算依赖在SQLite中共享保存，不再为未来任意重测保留两年档案。当前状态、最新续算检查点和活动段直接依赖保留；已完成段只留范围、质量和批次级增量摘要，不重复保存每个版本的完整累计状态。每月只保留当前有效结果，日汇总长期保留。模拟目录仍限1GiB并递归计量；不能为腾空间删除未消费输入。暂停导致必要输入积压时明确显示预算/缺档状态，不保证无限暂停后仍能追平。

接口基础为 `/api/platform/rule-lab/{batches|studies}/{id}`：

| 方法与后缀 | 用途 |
| --- | --- |
| `GET continuation-preview` | 只读资格、实际起点、不透明revision和最新请求回执 |
| `POST continuation` | 保存保留数据/自动续算开关及北京时间每日时刻 |
| `POST append` | 持久化手动追加请求；新等待返回202，幂等重试返回200 |
| `GET segments?limit=20&before_id=…` | 分页读取历史段，limit范围1～50 |
| `GET input-coverage` | 读取捕获/计算水位、质量、缺口及空间状态 |

POST均需 `request_id` 与预览返回的 `expected_revision`；同ID不同内容409，状态变化返回409供刷新。只有segments接受指定分页参数；继续沿用管理员、归属验证、16KB请求限制及no-store。schema v4为实验库加法迁移，默认不替现有实验开启采集或自动续算，不修改上游数据库和真实投注账本。
