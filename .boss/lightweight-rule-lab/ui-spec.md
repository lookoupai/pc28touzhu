# 轻量规则实验室 UI 规范

## 摘要

- 沿用现有 App Shell、工作台的白色表面、青绿色主操作及紧凑数据表；不增加外部字体、图表依赖或独立原型。
- 单页 `/rule-lab` 完成生成暂停批次、启动／暂停、比较结果、查看逐日与近期明细、导出 CSV；首版仅管理员可访问，批次仍按当前用户隔离。
- 每个候选成对使用 **OK 游戏网盘**与 **OK 游戏高赔常规**。首版统一固定金额、逐期跟随所选来源；前向模拟与历史回测分别标识。
- 默认读取汇总，展开详情才读取有界明细；手动刷新，提交后局部刷新，无持续高频轮询。
- 继承设计令牌；移动单列、平板双列表单、桌面三列表单，表格只在自身容器横向滚动。所有操作支持键盘与可见焦点。

## 1. 需求来源与追溯

需求来自当前用户授权及 `architecture.md`，不创建额外确认流程。

| ID（与 PRD 一致） | 需求 | 对应区域 |
| --- | --- | --- |
| R1 | 批量生成可理解的条件 | 生成表单、条件说明、50／78 版本数量 |
| R2 | 真实结算口径，仅两种 OK 规则 | 结算说明、实赔／退本／全亏、净收益 |
| R3 | 历史与前向分开 | 模式标签、历史限制说明、阶段与时间 |
| R4 | 低资源与可恢复 | 工作状态行、资源预算、启动／暂停 |
| R5 | 结果可长期比较 | 结果表、每日汇总、近期明细、CSV |
| R6 | 可操作且适配手机的页面 | 完整生成→运行→比较流程、响应式布局 |
| R7 | 业务隔离 | 模拟说明、管理员入口、拒绝访问与用户隔离 |
| R8 | 共用精简输入与保留边界 | 输入不足／缺期提示、明细保留说明；输入共享由后台实现 |

## 2. 信息架构与页面布局

导航使用现有管理员可见规则；入口文字“规则实验室”，地址 `/rule-lab`。普通用户不显示入口，直接访问显示既有拒绝访问页；前端隐藏不替代 API 鉴权。

从上到下：

1. **页头**：标题“规则实验室”；说明“批量比较触发条件，使用固定金额模拟记账。”；右侧“刷新”。
2. **运行状态行**：后台状态、最后处理时间、已保存实验数、存储使用量／预算。仅显示实际 API 提供的值，缺失显示“—”，不推断服务在线或伪造资源实测。说明可展开查看 CPU／内存预算及明细保留期，路径、凭证、内部数据库结构不展示。
3. **生成批次**：初次无批次时展开；已有批次时可折叠。字段与数量预览见下一节。
4. **我的实验批次**：选择一个批次；行中显示名称、模式、状态、实验版本数、观察／回测区间、查看／启动／暂停。批次列表最多 50 个，超过由服务端拒绝新增；页面可本地分页，保持选择。
5. **批次结果**：标题、模式、阶段、批次更新时间、启动／暂停、导出 CSV；结果表；展开的实验详情。

不使用模态框承载结果或表单，不设置“冠军规则”推荐。净利润排序与样本数并列，收益颜色不代表统计有效性。

## 3. 生成表单与契约

单个批次选择一个预测器与一个玩法。字段必须与 `architecture.md` §5 完整一致；初始草案经架构角色对齐如下。

| 标签 | 字段 | 控件及验证 | 默认 |
| --- | --- | --- | --- |
| 批次名称 | `name` | 可见标签文本输入，必填，最多 80 字符 | 空；示例放提示 |
| 预测来源 | `predictor_id` | 从 options 返回的合法预测器选择，不接受任意路径 | 首个可用项或空 |
| 投注玩法 | `metric` | 大小 `big_small`、单双 `odd_even`、组合 `combo` | 单双 |
| 观察方式 | `mode` | 单选：前向模拟 `live`、历史回测 `backtest` | 前向模拟 |
| 每期模拟金额 | `stake_amount` | 有限数字，0.01～10000，最多两位小数，单位“模拟资金单位” | 1 |
| 开始日期 | `start_date` | 仅历史回测显示，必填日期 | 空 |
| 结束日期 | `end_date` | 仅历史回测显示，必填日期，不早于开始、不晚于今日，范围按服务端 90 天约束 | 空 |
| 条件模板 | `template_pack` | 只读“基础条件 v1” | `basic_v1` |

两套结算规则固定展示为文本，不提供其他结算选项，也不以可禁用复选框制造可以改变的错觉。可展开查看服务端提供的赔率和退本摘要，金额与结果按创建时冻结配置计算；界面只展示接口实际提供的规则名称和固定赔率说明，不宣称能查看未返回的完整快照。

数量预览对应契约固定的 `basic_v1`：大小／单双为 25 个条件 × 2 套结算＝50 个实验版本，组合为 39 × 2＝78 个；创建后以 `generated_count` 为准，`options.limits` 决定可用额度。当前阶段禁止自由输入超大枚举范围。

表单主按钮为 **“生成并保存”**，按钮下说明“保存后暂停，启动后开始模拟。”；成功显示“已生成 N 个实验版本，当前已暂停”，选中新批次、滚动到结果区域并聚焦区域标题。创建成功不自动启动。

模式说明：前向模拟“从启动后的可用信号开始观察，等待条件及开奖”；历史回测“按现存历史记录重放，结果与前向模拟分别统计”。切换为前向时隐藏日期，不发送历史日期。

API 字段错误显示在对应字段下，同时顶部摘要可聚焦；任何提交失败保留已填写内容。生成中禁止重复提交；当前创建接口没有幂等键，网络结果未知时先刷新批次列表并提示用户核对，不自动重新提交创建；状态修改可按后端状态幂等重试。

## 4. 结果与详情

结果表默认按条件顺序排列，两个结算版本相邻，便于比较。接口返回当前批次全部实验（最多 100 个），可在客户端按净收益／已结算期数／最大回撤排序和分页；切换排序保持批次、清空详情，回到第一页。不在客户端混合所有批次累计成一个收益榜。

核心列顺序：条件说明、结算规则、已结算期数、净收益、投注收益率、最大回撤、最长连亏、实赔／退本／全亏、样本状态、详情。条件说明必须人可读，例如“预测连错 ≥ 5 期”，不要直接展示 JSON。

- 金额固定小数，正数带 `+`，亏损保留负号；赔率可保留四位，避免丢失 2.846。单位为“模拟资金单位”，不冒充人民币或真实账户余额。
- 投注收益率定义为 `净收益 / 累计投注额 × 100%`；零投注显示“—”。回撤为资金曲线历史峰值到后续低点的最大下降额。
- 实赔、退本、全亏分开，不能把退款算作实赔。未结算或未执行不混入已结算期数。
- 样本状态使用服务端枚举／标签；没有达到最低样本只提示“样本不足”，不承诺达到某笔数就证明有效。没有置信区间字段则不绘制置信区间。
- 日期显示北京时间并明确标注；`updated_at` 标为“批次更新于”，不能冒充最新开奖时间或统计截止期。

点击“详情”在表格下方展开一个命名区域，内容为：完整条件、模板版本、结算规则名称、累计统计、最近每日成绩、最近逐期结算。只展开一个实验，按钮使用 `aria-expanded`；关闭后焦点返回原按钮。

每日表：日期、结算数、实赔／退本／全亏、投注额、净收益。明细表：期号、决策时间、投注方向、金额、状态、结果类型、净收益、退本／跳过原因（存在时）。当前 API 不返回三球开奖结果，界面不添加空壳开奖结果列。每日最多最近 90 天，明细最多最近 50 条，均为固定有界列表，没有服务端翻页；不得把最近明细误标为全部历史。

CSV 下载从已认证 endpoint 获取，仅导出当前批次结果。下载失败显示原始业务错误的安全文字，不把错误 JSON 保存成 CSV。按钮说明“导出当前批次结果”，不承诺完整历史明细。

## 5. 状态文案与反馈

| 数据状态 | 页面文案／行为 |
| --- | --- |
| `paused` | 已暂停；可启动；已有成绩继续显示 |
| `running` | 运行中；可暂停；同时显示当前阶段 |
| `completed` | 回测完成；可看详情、导出；不提供重新开始按钮，改变条件新建批次 |
| `error` | 处理异常；显示业务可理解的原因；仅后端允许时提供恢复 |
| `resource_paused` | 资源限制暂停；保留进度与成绩，展示具体资源原因及允许的恢复操作 |
| `warming` | 准备历史窗口；当前不足的窗口不判定为零命中率 |
| `observing` | 等待条件或开奖 |
| `importing` | 分批读取历史 |
| `replaying` | 正在回放历史；展示实际游标／日期，不伪造百分比 |
| `idle` | 等待任务 |

空、错误与中断：

- 无批次：“还没有实验批次。先选择来源与玩法生成候选。”同时展开表单。
- 无可用预测器：“暂无可用预测来源”；禁用生成，保留刷新。
- 暂无结果：“尚无已结算模拟结果”；如果 paused 提示启动，如果 warming／observing 展示对应原因。
- 历史不足／缺期／错过决策窗口：展示服务端计数和范围，不补零、不拼接未知序列；无法覆盖的日期明确标注。
- API 初次失败：局部错误框＋重试。刷新失败：保留旧结果，显示“更新失败，以下为上次读取结果”及读取时间。
- worker 心跳过期：使用后端判定，展示“后台暂未更新”，不将所有批次状态擅自改成暂停。
- 请求过程中离开页面：不依赖浏览器持续打开完成模拟；返回后读取服务端状态。

## 6. 令牌与响应式

唯一值表在 `ui-design.json.tokens`。页面样式使用已有令牌 `--bg`、`--surface`、`--line`、`--text`、`--muted`、`--primary`、`--danger`、`--radius-md`、`--radius-lg`；缺失的间距、字号、尺寸与断点由 `--lab-*` 令牌定义。不得用局部硬编码覆盖全局主题。正文与表单使用系统字体，不新增字体网络请求。

主体表面无阴影；边框分隔、留白组织层次。主按钮使用 primary，其他动作描边或文字。净收益始终显示符号，状态始终显示文字。

| 档位 | 令牌范围 | 布局 |
| --- | --- | --- |
| 移动 | viewport ≤ `breakpoints.mobile` | 表单一列，动作换行，标题与刷新上下排列；结果容器横向滚动，页面整体无横向溢出 |
| 平板 | mobile < viewport ≤ `breakpoints.tablet` | 表单双列；继承现有折叠导航；批次列表与结果上下排列 |
| 桌面 | viewport > tablet | 表单三列、名称跨列；批次与结果仍上下排列，优先给结果表足够宽度 |

批次及实验使用有界数组，可本地分页；不发送契约未定义的分页参数。长名称最多两行，完整名称在可访问详情中显示；不只依赖 hover title。表内数字不换行，条件说明允许换行。触控目标使用 `sizes.touchTarget`。

## 7. 组件八态与可访问性

| 组件 | 默认 | 悬停 | 聚焦 | 激活／选中 | 禁用 | 加载 | 错误 | 空 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 主要／次要动作按钮 | primary／描边 | primaryStrong／hoverSurface | primary 外轮廓 | 文字保持、轻微背景变化 | 原生 disabled＋提示原因 | 动作文案“生成中…”等，aria-busy，禁重复提交 | 所属区域文字错误，可重试 | 不适用；按钮必须有名称 |
| 文本／数字／日期输入 | 标签＋边框＋帮助文本 | 边框使用 muted | 可见焦点环 | 输入内容；无额外选中态 | 原生 disabled，不丢值 | options加载时依赖字段禁用 | aria-invalid＋关联错误 | placeholder 仅示例，必填校验 |
| 来源／玩法选择 | 标签＋选项 | 继承原生交互 | 可见焦点环 | 显示当前值 | 无选项或提交中禁用 | “加载来源…” | 标签下错误和重试 | “暂无可用来源” |
| 模式单选 | fieldset＋legend | 标签背景 hoverSurface | 原生控件可见焦点 | 原生 checked＋明确文字 | 原生 disabled | 提交中禁用 | 组说明错误 | 不适用，始终有默认值 |
| 折叠生成表单 | summary＋标题 | hoverSurface | summary可见焦点 | 展开状态与箭头 | 不适用 | 子表单各自加载 | 内联错误时自动展开 | 初次无数据自动展开 |
| 批次选择／分页 | 命名按钮 | hoverSurface | 可见焦点环 | 选中标记＋aria-current | 首／末页或请求中禁用 | 保留旧页并标记读取中 | 局部错误＋重试 | 空状态替代列表 |
| 排序表头／详情 | 明确按钮名称 | hoverSurface | 可见焦点环 | aria-sort／aria-expanded | 无结果时禁用相应操作 | 详情局部加载，不清空其他数据 | 局部可重试 | 无明细清楚标注 |
| 状态／指标 | 文字＋数值 | 不适用 | 不适用 | 不适用 | 不适用 | “读取中…” | 文字说明 | “—”表示未知，不以0替代 |

采用原生语义按钮、输入、单选、details/summary、表格表头与 caption；表格横向滚动区域可键盘聚焦并有标签。动态保存结果用 `role=status`，字段错误用关联文本；不要每次刷新朗读整个表格。异常告警使用一次性 `role=alert`，重复刷新不重复抢焦点。

对比度按最终 shell 白色表面验算：正文 14.57:1、次要文字 4.90:1、primary／白色 5.47:1、danger／白色 4.84:1、warning 文字／底色 4.88:1、成功文字／底色 6.39:1。可见焦点使用 primary，避免仅依赖现有较浅焦点色。减少动效偏好下取消过渡；此页不使用入场动画。

## 8. 验收与产物

必须验证：管理员生成暂停批次→启动→刷新读取真实状态→暂停→查看详情→导出；401／403／404；重复提交防护；零结果与异常恢复；长名称与恶意文本安全输出；桌面和窄屏无页面横向溢出；键盘可完成表单及分页；仅包含两套 OK 规则。

正式产物为本文件与 `ui-design.json`。未生成独立原型，未修改应用代码，设计契约以完整架构字段为准；字段更新须同步两份文档。

最终契约核对：API 成功直接返回对象；创建为 HTTP 201 `{batch, generated_count}`；其他查询 200。错误为 `{error, code}`。UI 不添加请求中不存在的路径、用户 ID、赔率、自定义条件或幂等字段；排序／分页仅在有界返回数组内处理。

修订记录：按 PRD 统一 R1～R8 编号；创建请求无幂等键，结果未知时刷新批次核对，不自动重提；金额保留两位、赔率最多四位（2.846 不缩写为 2.85）。
