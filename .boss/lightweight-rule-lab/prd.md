# 轻量规则实验室需求

## 摘要

- 来源：用户希望系统生成更多自动触发条件、批量记录效果，同时尽量少占用共用服务器资源。
- 最新约束：先核对两个项目的 GitHub 备份；仅模拟「OK 游戏网盘」和「OK 游戏高赔常规」。
- 首版提供有界模板生成、历史回放、从创建后开始的前向模拟、暂停恢复、结果/每日/最近明细/CSV。
- 固定金额单期跟随用于识别条件本身的效果；过关/倍投/机器学习搜索不属于首版。

## 用户原话

> 可以，你先检查两个项目还有没有之前修改需要上传 GitHub 备份的，没有的话就可以做，结算规则我们暂时先只用 OK 游戏网盘和 OK 游戏高赔常规吧，其他规则差得不太多，没必要浪费资源都模拟一次。

## 验收要求

| ID | 要求 | 验收 |
|---|---|---|
| R1 | 批量生成可理解的条件 | 默认一次生成约50个实验版本；每个条件对应两种且仅两种OK预设；有无条件基准 |
| R2 | 真实结算口径 | 使用已有冻结结算函数，实赔、退本、未中分别计数；命中不冒充盈利 |
| R3 | 历史与前向分开 | 模式明确标识；前向决策须在目标期开奖前冻结，历史回放不能冒充前向 |
| R4 | 低资源与可恢复 | 一个worker，CPUQuota=20%、MemoryMax=256M、模拟目录1GiB预算；分页、短事务、游标和状态原子提交 |
| R5 | 结果可长期比较 | 累计与每日统计、最大回撤、最长连亏，最近明细和CSV；清理明细不损坏累计 |
| R6 | 可操作的页面 | 生成、暂停/继续、查看结果、按日和最近明细、导出，适配手机 |
| R7 | 业务隔离 | 模拟库独立，源库只读，无派单/消息；管理员入口仍按user_id隔离实验 |
| R8 | 输入与数据保留 | 共用精简三球开奖/预测输入；不复制原始正文，不每条规则复制输入；清理不能越过活动任务需要的数据 |

## 边界

首版固定金额、单腿大小/单双/组合，按来源下一期预测跟随；不创建或修改实盘自动规则。50～100版本是起始规模，不是保证能盈利。历史回放基于当前留存预测版本，须展示它不是不可变原始预测档案的限制。精简输入只覆盖收集到的区间，已被上游删除的数据不能恢复。
