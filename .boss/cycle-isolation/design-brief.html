设计简报

文档信息

  • 功能名称：cycle-isolation / 手动与自动过关运行隔离
  • 创建日期：2026-11-04
  • 需求来源：用户运行复盘与“那你开始设计方案开工吧”的明确授权

1. 需求背景

用户已将手动跟单与自动规则的盈亏计算分开。新增过关玩法把每日轮数、达标与爆仓处理放在跟单策略中；自动规则首次启动后又沿用策略的当天收工状态。这使用户无法表达“每轮结束后等待下一次条件，每天最多启动 N 次”；同一方案的手动与自动过关状态仍可能相互影响。

已观察到的实例：规则“jnd28波动反弹模型 过三关 连出2次大双”以单＋大双结构启动，第三关失败后按方案的爆仓当天收工设置停止，自动规则不能独立决定等待新条件。本期不改变该已停止实例的设置和账本。

2. 目标用户

现有用户会复用同一来源和投注方案，分别手动运行或由多条自动规则启动。他们需要在各自入口查看该归属的关数、滚仓金额、次数及停止原因；操作其中一方不得隐式改变另一方。

3. 核心场景

  1. 连续两期大双启动“单＋大双、起始 10、过三关”，结束后等待新的条件，当日最多启动 3 次。
  2. 自动规则也能选择直接续开；该模式免重新满足条件和再次触发冷却，但仍检查日额度、日风控和可投信号。
  3. 同方案手动运行与多个自动规则分别推进和结算，继续遵守既有目标冲突与防重复投递约束。
  4. 手动停止/重置只改变手动状态，自动入口操作只改变明确选定的规则范围。
  5. 升级保留在途单、账本、次数和当天停止，不重复发送、不自动补仓、不解除收工。

4. 约束与偏好

  • 复用现有页面、权限、派单、结算与统计口径，不引入新框架或运行依赖。
  • 新规则默认每日 1 轮、结束后等待条件；日额度用尽后停止新增轮次。
  • 存量规则默认保留旧行为，以明确兼容配置呈现，普通改名或保存不得采用新默认改变行为。
  • 每日次数按“自动规则＋跟单方案”统计；同规则多个路由不重复扣次，不增加路由独立结构设置。
  • 跨日未结束的轮次保持金额、进度和任务到终态；计次归启动日，不因午夜另开重叠轮次。
  • 本任务不修改线上数据库、不重启服务、不发 Telegram 消息。

5. 已定口径与开放问题

无阻塞性业务问题。赔率、退本、整数下注、两腿合计净利等口径维持现有算法。存储结构、迁移方式和 API 字段由架构文档定义，并满足 PRD 的隔离与兼容验收。
