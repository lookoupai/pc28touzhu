1. 概述

1.1 背景

用户原话：“我们之前就将手动跟单方案和自动触发规则的计算都分开了，也是考虑到手动和自动的问题，所以设计功能时是不是也都需要考虑两边分别都支持。”随后明确授权设计并开工。

现状把过关日轮数、达标/爆仓处理和运行状态主要放在跟单策略，自动规则只有开始条件与冷却。用户不能完整配置“结束后回到待命，再次满足条件才开下一轮，每天最多 N 次”。运行归属也没有像盈亏账本一样完全隔离。

1.2 目标和成功指标

  • 同方案手动运行和至少两条自动规则分别结算、结束、停止、重置时，其余归属的金额、关数、日次数和停止标记不变。
  • 每日上限 N 生效于所有自动新开轮路径；重复检查、并发检查和重启不会多计或漏计启动次数。
  • 等待条件模式无新证据时不续开；直接续开免重新匹配条件及再次触发冷却，但仍遵守风控、次数和信号可投窗口。
  • 升级前后历史净盈亏、待结算金额及任务数量一致，已收工状态保持停止。

1.3 需求分层

层级内容来源或推导依据
显性手动与自动分别支持过关管理，自动规则控制每日启动次数用户追问功能归属并明确要求两边都支持
隐性不同自动规则互不影响；重置范围明确同方案可被多条规则引用，分开盈亏应延伸到分开运行
潜在迁移在途状态、重复启动和跨日额度必须准确现网已有实盘轮次，升级时可能有未结单或收工状态
惊喜本期不扩展额外功能聚焦运行正确性，不增加无关策略和统计

2. 用户画像与核心流程

用户是现有平台操作者，已经会配置来源、过关结构与自动条件，期望在熟悉的入口分别控制手动和自动运行，无需理解内部存储方式。

自动等待条件流程：条件满足 → 有可投注新信号且额度/冷却/风控通过 → 启动一轮 → 达标或本轮可滚金额耗尽 → 全部腿结算完成 → 返回等待条件或当天收工。

自动续开流程：本轮结束 → 待续开 → 额度/风控和信号窗口通过 → 建立新轮。“直接续开”表示免重新匹配开始条件和再次等待触发冷却，不表示绕过日限制或立刻发送不可投信号。冷却期数仅约束再次通过条件启动。

手动流程沿用现有手动开始、目标关数、达标/爆仓处理及收工行为，不再充当自动规则的共享状态。

3. 功能需求与验收

P0 是缺失就不能交付本目标的功能，优先价值高，允许必要的跨模块成本；P1 是使设置可解释的界面增强，复用页面即可完成。

ID需求与层级优先级及依据Given-When-Then 验收标准
FR-001手动与自动状态隔离；显性P0：直接解决用户问题Given 同一方案有手动和自动运行，When 任一方结算、达标或爆仓，Then 只改变本归属的关数、金额、次数和停止状态，另一方按自己的状态继续。
FR-002不同自动规则隔离；隐性P0：复用方案不能串状态Given A、B 两条规则引用同一方案，When A 结束、冷却、收工或重置，Then B 的状态和额度不变；相同投递目标上的原有冲突保护仍有效。
FR-003规则独立配置跨轮行为；显性P0：表达每日多次条件启动Given 新建过关自动规则，When 保存每日 3 轮、达标后等待条件、爆仓后当天收工，Then 重载一致并按此执行，手动策略的结束动作不覆盖自动配置。
FR-004自动继承投注参数；显性P0：保留结构自由组合Given 方案为单＋大双、起始 10、目标 3 关，When 自动条件触发，Then 使用这些投注参数；观察大双或小单均不改变投注结构。修改方案不重写已派任务和在途轮次参数。
FR-005结束后等待条件；显性P0：核心入场场景Given 结束动作是等待条件且剩余额度大于 0，When 本轮全部结算后无新的已开奖期满足条件，Then 不开新轮；When 完成期之后的新已开奖证据满足条件且其他门槛通过，Then 只新开一次。已消费的触发期不得复用。
FR-006直接续开；显性P0：保留用户可选控制Given 结束动作是直接续开，When 全部腿终态且额度/风控/信号窗口允许，Then 按每轮起始参数建立新轮，免重新匹配开始条件和再次等待触发冷却；无可投信号时等待，不提前记作已派发。
FR-007每日启动额度；显性P0：防轮询及续开绕过上限Given 同规则同方案每天上限 N，When 任一路径新开自动轮，Then 共用同一额度；两腿、多个路由不重复计次。第 N 轮可正常完成，之后不再新增；无可投信号或未匹配条件不耗次数。
FR-008冷却及日风控继续有效；隐性P0：新模式不得绕过已有约束Given 冷却未满，When 等待条件模式尝试再次触发，Then 被阻止且原因可见；Given 日止盈止损生效或规则停用，When 任一模式尝试启动，Then 均被阻止。直接续开免触发冷却，本轮正常续投不重复扣次数。
FR-009手动行为保留；显性P0：用户明确要求两边支持Given 手动方案选择收工、重开或达标继续滚，When 到达对应边界，Then 按原设置处理；手动日轮数只统计手动运行，不占用自动额度。
FR-010停止/重置/恢复范围；隐性P0：避免一方意外解封另一方Given 手动和自动均有状态，When 在手动入口重置或开始新一轮，Then 自动的在途计划、日额度、关数和收工均不变；自动入口也只影响明确选定规则。单纯重置盈亏不解封收工状态。
FR-011跨日与在途轮次；潜在P0：午夜不得重复开轮Given 午夜前启动的一轮尚未结束，When 日期变化，Then 保持旧轮金额、关数、待结算计划直到终态，不另开重叠轮；启动次数归启动日，之后的新轮用新日额度，盈亏仍按原结算日期统计。
FR-012存量兼容和迁移；潜在P0：现网记录不能丢失或误恢复Given 旧规则没有新字段，或旧状态有在途单/当天收工，When 升级并加载，Then 保留原调度行为及可确认的运行归属，账本不变，无重复任务、自动补仓、自动解封；归属不明则阻止受影响状态启动并提示，不复制为多份可用资金。
FR-013状态展示和保存校验；隐性P1：避免把等待误认为故障Given 存在手动与自动运行，When 查看各自页面，Then 展示本方关数、今日已用/上限、运行/等待条件/待续开/当天收工及原因；非法次数/动作拒绝保存，旧配置回显不改变行为。

3.1 配置和计数语义

  • 每日最多启动次数为正整数，包含当天第一轮，按“规则＋关联方案”分别统计；不同关联方案不相互抢占次数。
  • 达标后、爆仓后分别支持等待条件、直接续开、当天收工。
  • 新规则默认每日 1 轮、两种结束动作均为等待条件；用尽当日额度后不再启动。设置为多轮后才会在同日再次等待或续开。
  • 旧规则通过明确兼容方式保留升级前行为；打开旧规则、改名或保存普通字段不能隐式使用新默认。
  • 过几关、起始金额、结构、滚仓方式归投注方案；自动新轮继承，运行中参数与已发送任务保留本轮快照。
  • 当天收工、日风控与停用优先于续开。新轮重置本轮进度和起始注，不清零规则当日累计盈亏。触发冷却仅用于再次等待条件的启动；选择直接续开后不重新等待该冷却。
  • 只有显式选择直接续开或条件重新满足，且所有门槛允许时，才可按起始参数开始下一轮。升级与缺省配置不隐式补仓。
  • 自动状态与配置缺失时不能静默读取手动运行进度充数；兼容展示须明确其归属与行为。

4. 异常、边界与非功能需求

场景预期行为
同期开奖被重复/并发检查同归属只启动一次，轮次数和事件一致。
一腿送达、另一腿失败或过期沿用原结算口径，全部腿终态前不重开，不混入其他归属的腿。
同规则多个路由启动额度按一轮扣一次，继承同一结构；不新增路由独立结构配置。
触发命中但信号已开奖/封盘保持等待，不提前记成已启动/已派发。
达标后次数用尽或日风控命中不续开，显示具体原因。
调低上限到已用次数以下只阻止新启动，不中断当前轮。调高上限不自动解除已有日收工/风控停止。
午夜旧轮未结且新条件满足先完成旧轮，随后评估新日额度；无重叠开轮。
手动重置有在途单沿用在途保护，不清除自动归属的待结算计划。
迁移归属不明保留原证据并阻止受影响状态自动开始，不猜测、复制或丢弃。
越权访问/修改维持既有用户归属校验，不暴露或改变他人运行状态。

本次不虚构用户规模或延迟指标。所有金额沿用现有精度、整数下注、尾差、退本与赔率口径。回归验证在隔离数据库执行，不以真实投注消息验证功能。不引入新框架或运行依赖，保持现有 UI 交互、认证和 API 风格。

5. 用户故事

  • US-001：作为自动规则用户，我希望一轮结束后重新等待连续两期大双，最多每天 3 次，以便控制每次入场。验收对应 FR-003/005/007/008。
  • US-002：作为同时手动和自动运行的用户，我希望手动收工不影响自动，以便运行归属与盈亏归属一致。验收对应 FR-001/002/009/010。
  • US-003：作为现有用户，我希望升级后未结单延续原轮、已收工规则保持停止，以便升级本身不产生投注。验收对应 FR-011/012。

6. 范围定义

6.1 范围内

运行隔离、规则跨轮配置与日额度、手动兼容、明确归属的重置/停止/恢复、迁移保护、页面状态及回归验证。存储和 API 契约由架构文档制定。

6.2 不做什么

  • 不同路由选择不同过关结构：用户明确推迟。
  • 不增加预测算法、开奖条件、赔率或投注品种。
  • 不重算或改写已入账盈亏，不将平台策略余额解释为外部账户实际余额。
  • 不修改现网规则轮数，不解除现网收工，不自动补仓或发 Telegram 消息。
  • 不新增认证、框架、数据库服务或部署设施。

8. 假设与已定事项
