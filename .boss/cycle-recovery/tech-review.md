# 异常周期恢复技术评审

## 摘要

- 结论：有条件通过。将执行生命周期与对账生命周期拆开，满足用户明确要求；旧HTML“对账完才开新轮”的部分不再适用。
- 最小可行实现为增量run档案、一次性本金占用和下一开轮边界消费credit；不重建全周期主表，不引入新框架。
- 主要阻塞风险是重复扣保留资金、迟到回执覆盖新周期、未决档案被清理、人工stop被误解锁及多路由漏归档。下列验收须通过。
- 代码在隔离worktree开发；用户已经授权本次修复及按轮次隔离的数据改动。无需重复请求设计里已经明确的实现授权。

## 评审依据

基线43fd8a2。源码核查定时开轮事务、来源续派、两腿合并、领取/回报幂等、逐腿财务归属、周期推进、手动停止和正文/运行保留。此前现有9组144测试47.993秒全过，但不覆盖这次异常恢复。已离线复现EOF在connect被误分类、同attempt补强被去重、全void后run仍running、cancelled不被周期解析器识别。

## 必须解决

| 级别 | 问题 | 必须实现的约束 |
| --- | --- | --- |
| Blocker | 当前表不含run主键，直接新开覆盖pending | 同事务先写不可丢的完整run/route档案，再释放current/session |
| Blocker | 保留本金可能重复扣或旧赔付污染当前 | K/R快照与唯一归档；credit=R+N-K；新开事务最多消费一次；当前stake/关数不改 |
| Blocker | 多路由及in-flight发送 | 归档全部参与路由；placed保留待结算；发送中视未知，关闭未来发送资格 |
| Blocker | unknown被清理/作废 | 无证据不得void、refund、miss；未决档案及其原事件/运行归属受保留保护 |
| Blocker | 人工stop/风控被自动恢复 | 只清执行占用，不清独立阻塞；正常跨日placed不得因年龄/日期结束 |
| Major | 最外层异常一律unknown | 发送前阶段准确分类IncompleteReadError/EOFError，发送后保持未知 |
| Major | 不可见历史风险 | 同时展示运行已结束和历史保留本金，区分策略余额/补充本金/真实钱包 |
| Major | 同attempt后续证据 | 独立审计补强，不能放宽重复report任意覆盖；新证据单调推进 |
| Major | 无限历史扫描 | 按未决/期限索引有界批处理；背景查证独立频率，不拖延新单 |

## 取舍

`max(balance,base_amount)` 是原有自动补基础本金策略，不是实时真钱余额风控。可继续沿用，但补充金额须审计和展示，不能以“扣保留本金”宣称已经校验目标账户实际可用余额。all_in按独立新本金运行，历史credit不更改新轮base。

允许无证据档案长期未决，但它不再占用运行会话。人工核对只处理历史争议，不属于每期/每日调度条件。禁止为查证发送测试投注或依开奖输赢推断是否下注。
