# 双组、杀组发布准备

## 摘要

- 两项目代码已实现，使用说明为 `docs/GROUP_PLAYS.md`。
- 本次完成本地代码与临时数据库验证，没有推送远程仓库、重启生产服务、运行生产迁移或启用实际投注。
- 用户要求不使用子代理，初始架构子代理已停止；后续工作全部由主代理完成。

## 发布范围

投注端更新领域、仓储、派单/结算、来源标准化、规则/Bot 和页面；来源端更新命名、执行导出、表现统计与收益模拟。没有新增运行依赖、修改认证模型或修改部署配置。

数据库初始化的兼容变更：

1. `subscription_progression_events.prediction_hit INTEGER` 可空列；旧记录保持 NULL。
2. `idx_normalized_signals_source_issue_metric` 查询索引。
3. 使用 `profit_report_group_stats_v1` 标记升级日报触发器；保留原回填标记，不重复回填历史资金。

## 启用顺序

在正式发布窗口同步两项目代码，使投注端 API、来源同步、自动触发、结算和执行相关进程加载新代码，再创建或修改双组/杀组方案。既有 all 订阅不会自动加入新玩法；来源 URL 无需强制更换，若直接导出新玩法则增加 `include_group_plays=1`。

发布前按现有运维方式备份数据库。回滚时先停用新玩法并处理其在途记录；旧版代码不能结算新组事件。新增可空列和索引可以保留，不能靠删除历史事件回滚资金。

## 验证范围

浏览器测试仅运行 `tests/group_ui_server.py` 的临时数据库服务，允许本地配置保存，禁止外部请求和发送接口；本地模拟回执只写测试库。截图和测试日志位于 `evidence/`。

未执行生产负载、真实 Telegram 群接收或生产服务重启验证；不将本地测试视作已上线。
