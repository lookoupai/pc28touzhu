# 列表观察规则 UI 规范

## 摘要

用户已确认在实验列表直接比较月度收益、回撤、样本和近期表现，并允许配置阈值与高亮。采用现有规则实验室的浅色中性界面，做中等程度的列表结构调整；增加一个共用规则面板，保持页面路由、实验操作和资金换算功能。统计/API字段以 `plan.md` 冻结契约为准。

## 布局与交互

- 在批次结果、比较结果之前放置一个页面级“列表观察规则”面板，共用规则作用于两种列表。折叠时显示当前规则摘要；展开后修改并点击“应用规则”，校验成功再生效。提供恢复默认。
- 基础项：连续自然月数（2/3/6快捷按钮与1～12整数输入）、月份口径（包含未完整月/仅完整月）、每月最低投注收益率（默认3%）、每月最少结算笔数（默认200）、每月最少投注日（默认10）。
- 可选限制：收益率月间差距（百分点）、最大月度日结回撤（原始每注的倍数）、最长回撤恢复时间（日）。空白表示不限制，不把零和空白混用。
- 展示项：完整达标高亮色（红/蓝/紫）、仅看符合规则、显示运行信息。红色为用户自选匹配标记，不替换现有净利正负颜色；阶段达标固定橙色，所有颜色同时有文字标签。
- 应用规则仅写入本设备同站点的展示偏好，不修改实验或续算配置。月份/口径变化时一次读取当前批次、一次读取当前比较组；其他阈值或颜色改变直接用已读数据重新筛选。响应绑定请求版本和月份回显，过期响应不能覆盖新规则。
- localStorage 不可用时继续在本页生效并提示；损坏或不合法的已存配置恢复默认，不能使页面无法打开。

## 列表信息层级

默认列：

1. 条件与结算（比较组另有风控方案）；条件名称保留原文。
2. 观察状态：完整月达标、阶段达标、未达标、历史不足、样本不足、数据需核对；显示首个不满足原因和实际截止日期。
3. 近月收益：各月投注收益率、最低值、月间差（pp）。无样本/缺月显示“—”，不以零盈利或静默跳过处理。
4. 风险：月内日结回撤范围与原始注额倍数；累计逐笔回撤另标。
5. 样本：最少月份的结算笔数与投注日数；原始累计结算数保留为次级信息。
6. 近期表现：最近14天ROI及笔数、前14天ROI；不足窗口时明确覆盖限制。
7. 累计成绩：净利、累计投注收益率；比较组保留同条件相对基准的差值。
8. 操作：详情、月度成绩；行内“更多指标”显示去除最佳3天后的净利、恢复时间和最长连亏。“运行信息”开关显示原轮状态、统计日、当日/本轮盈亏、停止原因。

状态、月度收益与风险为首要阅读对象，不把所有金额均设成醒目颜色。每个单元用最多两级字号与行距组合信息，避免堆叠多色徽章。批次和比较组复用同一观察单元，筛选、分页在完整过滤结果上进行。

## 统计展示边界

- 默认2个月且包含未完整月；有一个部分月时即使经济阈值满足也只能标“阶段达标”。仅完整月模式当前只有一个完整月时显示“已有1/2个月”，不得缩为一个月评价。
- 收益达标与月间波动相近分别呈现。收益率差距阈值只有用户设置后才作为硬限制，不以“收益更高导致月间差更大”自动判为坏方案。
- 严重缺档、输入冲突、旧算法需复核、不可比等状态优先于达标；正常的已知跳过显示说明，不能一概视为无效。
- 每个月门槛按原始整数分净利/投注额计算，不能用已四舍五入的展示收益率判断。
- 金额按原始模拟注额呈现；详情中的金额估算不会改变列表筛选、原始成绩或存储。
- 去除最佳3天只是结果敏感性检查，不代表重新回测或未来收益预测；恢复时间按日结数据，日内风险可能更高。

## 响应式与无障碍

沿用44px触控高度、可见焦点、原字体和间距。桌面规则表单使用三列，窄屏按一列重排。结果表在手机端允许自身横向滚动，页面整体不得因此溢出；关键状态文字与月份列优先可见。折叠项使用原生details/summary，表单字段关联label与错误提示，加载使用aria-busy、反馈使用role=status；用户不需要辨色即可理解所有状态。

## 验证

使用实际WSGI临时库和jsdom执行真实页面脚本，不打开浏览器进程或用户配置。测试规则编辑/保存/恢复、刷新后的偏好、完整月与阶段/缺月/样本边界、金额舍入阈值、仅匹配分页、批次与比较组一致、过期响应和失败回退、不可用localStorage、XSS文本、原详情/金额换算/管理/续算入口。视觉布局只能报告DOM与CSS规则检查结果，不声称截图测量。
