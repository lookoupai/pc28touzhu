# 规则实验室：以模拟结果为中心的存储修订方案

状态：设计完成，尚未开发、迁移或清理生产数据。设计基线：`d5a200a` / schema v5。日期：2026-11-27。

## 1. 用户目标与本次决策

用户需要比较不同入场条件、止盈止损、熔断、冷却等参数组合的模拟结果，并持续追加结果。实验室不是历史逐笔查询或审计档案产品。

**最终决策：结果长期保留，运行状态按依赖保留，已结算逐笔记录和已结束轮次不保留。** 不再采用前一轮讨论的“最近50笔、30轮”，也不建设压缩逐笔档案。增加一组参数应主要增加配置、累计状态和每日结果，不能再增加一整套长期逐期明细。

这份设计替代旧增量方案中“约两年输入档案”“已结算明细按入账时间保留30天”“任意旧区间的全历史金额重测”“永久保留每段完整检查点和报告历史版本”的范围；继续保留已实现的增量计算、时间可见性、冻结配置、暂停恢复、比较组共同输入、所有者权限及资源限制。

本次交付只修改设计资料。线上仍执行旧保留逻辑，不能把本文的目标写成已释放空间。

## 3. 产品范围

### 3.1 保留的结果

- 冻结参数：来源、玩法、条件、金额、赔率、止盈止损、熔断和冷却配置，以及算法版本与实际回测区间。
- 总体表现：投注/结算/命中/退本/亏损次数、金额、净收益、ROI、逐笔口径累计最大回撤、最长连续亏损、输入质量与跳过统计。
- 风控表现：开轮数、已完成轮数、盈利/亏损/持平轮数、单轮止盈/止损次数；日止盈/止损/命中率熔断触发日数、因风控停投的期数按明确口径追加统计。
- 每日结果与资金曲线、按日汇总生成的月度结果、不同方案对比和结果CSV。
- 计算/结算进度、未结算数量、是否同区间可比、缺失输入范围。

逐笔最大回撤与日终最大回撤仍为不同指标；最大回撤不能相加，ROI不能平均各日百分比。保留现有计算定义，不因空间改造改变结果。

新增的熔断触发日数/停投期数不能凭累计收益推算。迁移时只有现存记录足以准确重建的部分才补齐；否则用`not_recorded`及统计起算时间表示，不能填0冒充过去从未触发。

### 3.2 移除的用途

- 不保存、展示或导出完整历史逐笔投注；移除“最近逐笔”“最近已结束轮次”区块，不转移到另一份文件归档。
- 不保留任意旧计算段的完整恢复副本，不提供任意历史段回滚。
- 不保留所有旧月报修订副本。保留当前日/月结果及必要的缺样/修订说明。
- 不保证超出实际可用输入范围的原区间重测。旧成绩仍可查看，不等于旧年月仍可重新模拟。
- 不新增大规模参数生成器、不提高650保存版本/100同时运行上限；本次改造使未来参数扩展不会重新积累逐笔账本。

## 4. 数据保留契约

| 数据 | 保留规则 | 清理条件 |
| --- | --- | --- |
| 配置、累计成绩、日汇总 | 作为结果长期保留 | 用户删除实验时按归属删除 |
| 月结果 | 从日汇总计算；需要封账存储时每版本每月只保留当前结果 | 旧显示快照无运行依赖即可移除，不删日汇总 |
| `lab_decisions` | 仅未结算模拟记录 | 结算或跳过入账成功后，同事务删除；不留下终态行 |
| 已结束轮次 | 不保留逐轮记录 | 累计轮指标更新成功后，不写入或删除闭轮记录 |
| 当前活动轮 | 以`risk_runtime_json.active_round`为权威 | 闭轮并更新累计值后移除；旧表临时镜像只在迁移期保留 |
| 风控日状态 | 当前模拟日、最近状态展示日和未结算依赖的日 | 已结束且无活动/迟到结算依赖后清理；日成绩仍保留 |
| 去重水位、模拟时钟、资金高点、冷却状态 | 当前权威状态持续保留 | 不随逐笔清理倒退或删除 |
| 检查点 | 当前持久状态、最新可续算检查点、活动段直接前置检查点 | 新检查点落盘且无活动依赖后删除旧完整payload |
| 计算段 | 保留身份、范围、完成/质量摘要、输入hash和幂等关联 | 已完成段不保留每个版本的完整状态副本；保留必要标识避免ID/请求复用 |
| 开奖/预测输入 | 同来源共享，保存当前回放、暖机、待结算、未消费输入所需范围 | 无消费者依赖后清理，不以90天/两年为默认历史保留目标 |
| 覆盖明细与输入版本 | 只留受保护范围内实际可能读取的版本 | 消费完后先保存质量/完整性摘要，再删除逐期覆盖行和多余版本 |
| 幂等回执、ID高水位 | 小型控制元数据 | 不为省小量空间破坏重试与身份安全；回执不嵌套整套成绩副本 |

原实验的旧成绩、参数和运行身份保持。保留日汇总会随“版本数×天数”增长，这是结果本身的成本；不承诺任意多版本无限年限固定体积。

## 5. 计算与落库流程

```mermaid
flowchart LR
    A[共享预测和开奖输入] --> B[当前期条件特征]
    B --> C[有界批次中的不同参数组合]
    C --> D[待结算状态]
    D --> E[同一事务更新累计结果 / 日结果 / 风控 / 水位]
    E --> F[移除已结算记录和闭轮记录]
    E --> G[结果列表 / 对比 / 日月曲线]
```

每个参数版本单独维护必要累计状态，不按每个版本复制输入。相同来源、冻结输入版本和可见时点的特征可在一个tick内共用，不能跨不同冻结版本混用缓存。批量参数分组排队，继续遵守100个同时运行、1核/256MiB约束，不把全部版本和全部历史读入内存。

以后增加风控/熔断类型时，必须声明它的最小状态：例如连续亏损只需当前连亏计数，日止损只需当日净值，累计回撤只需资金高点与当前权益，最近N次命中率只需有明确上限的N项窗口。需要有限窗口的规则将窗口保存到当前运行状态，随提交原子更新；不能以“将来可能分析”为由恢复永久逐笔日志。规则无法给出有界状态和容量估算时，不进入批量运行。

### 5.1 结算必须原子化

在现有`commit_step`事务中，依次校验revision/状态及时间边界，按期号顺序找到pending，更新stats、日账、当前风险状态和决定/结算水位，最后删除该pending。全部成功才提交。崩溃只能得到“pending仍在且结果未入账”或“结果已入账且pending已移除”两种状态。

- 新决策仍受批次`last_issue_no`和实验`last_decided_issue`约束；不能只依赖逐笔表的UNIQUE去重。
- 重复结算必须先找到pending，找不到则无新增收益；不能因为已结算行被删除而重新插入/计数。
- 较早pending未解决时，不处理它后面的结算，保持回撤与连亏顺序。
- 输入冲突、缺失或权限失败不能伪造结算，也不能为压缩空间丢掉pending。
- 每笔金额仍按原结算规则逐注舍入，以整数分累计；不是将旧收益按金额倍数缩放。
- 熔断“触发日数”以日内首次进入停止状态计一次；“停投期数”在该实际期的游标提交中计一次，重试/刷新不能重复增加。

### 5.2 状态不再反查历史明细

迁移补齐并维护`cursor`中的实际首尾开奖时间、已结算结果最晚可见时间、模拟时钟和质量摘要。当前`_snapshot`对历史开奖求MAX、旧接管检查按`last_settled_issue`回查开奖、月报按首尾期回查日期，都要改为读取这些持久边界或必要检查点。

无法验证的旧边界应阻止相应续算并给出原因，不能用“现在时间”或窗口末日代替。已知缺预测/晚预测不因清理而消失；政策删除的旧输入不能被重新标成当时未采集的缺档。

## 6. 输入依赖与共享清理

清理前在同一写事务内计算所有消费者保护集合；包括普通回测、实时模拟、已完成但可接续的批次、暂停批次、队列待启动项、比较组和正在准备的新重测。不能只看`status=running`或是否存在series。

保护集合是以下**区间与离散期号的并集**，不能仅取最早pending期号然后保留到现在的全部跨度：

1. 每个已开始批次实际处理水位前100期暖机，并保留冻结方向、可见时间和缺样证据。
2. 每个pending对应的预测/开奖与必要状态更新；超过暖机窗口的pending单独保护。
3. 当前活动段未消费范围及固定revision；比较组保留至最慢的仍需该输入的子方案消费完成。
4. 已明确排队或暂停的回放尚需区间；未开始任务的日期范围先解析为有限实际期号范围，不能把“游标为空”解释为保护全部数据库。
5. 已启用采集的系列从消费水位到采集水位的未消费输入；已有上游重查窗口及确需重查的pending。

同一预测器按以上集合共享数据；开奖由所有预测器共同引用。对于每个受保护期，保留每个活跃冻结revision实际选中的版本及暖机精确引用，不得将历史所用方向替换为最新修订。方向不变的pending→settled状态更新仍可在正确可见时间后推进。

已完成但未启用连续采集的批次，只留未来接管需要的暖机及边界状态；不为潜在的金额重测继续保留整个旧区间。首次接入续算改为保存暖机/前沿和新增输入，取消把原回放全区间再次seed进档案的行为。

普通缓存和版本档案不再同时保留长期重复副本。过渡期若某个旧读取路径仍依赖缓存，必须先完成读路径切换与校验，再删除相应缓存。

### 暂停和积压的边界

暂停计算不等于可以删除尚未计算输入。必要积压仍可能增长，应显示占用来源和最早未消费区间；预算不足时先维护可清理数据，再暂停新计算/采集并明确提示。不能为满足一个漂亮的体积目标删掉待算数据，也不承诺无限暂停后仍能追平。

新的不同参数实验，从上游实际仍可用的范围或仍被现有计算保护的输入创建；先验证完整覆盖并取得保护，再返回创建成功。上游已清掉且实验库也无依赖保留的区间，不再支持重测。缺数据时返回明确范围，不能截短日期、填0或伪称与原输入相同。

## 7. 数据模型与索引变更

建议schema v6采用小幅增量迁移，不新建冷档文件、逐笔历史表或独立归档服务。

| 落点 | 设计变更 |
| --- | --- |
| `lab_decisions` | 改为pending工作表；迁移期间可并存旧终态行，服务声明`results_only`后只返回运行所需字段 |
| `lab_rounds` | 停止写闭轮；已有`risk_runtime_json.active_round`接管当前轮读取，清掉无依赖旧轮 |
| `lab_experiments.stats_json / risk_runtime_json` | 保持已有结果字段与水位；新增统计带`metrics_version`/起算范围，不伪造旧指标 |
| `lab_daily` | 继续每实验每日期一行，增加必要的风控统计；月报复用日汇总 |
| `lab_batches.cursor_json` | 增加可独立保存的首尾时间、结算可见时间前沿、必要数据保留版本；原游标不改 |
| `lab_checkpoints / lab_segment_batches` | 只保存当前运行依赖的完整状态；旧段清理完整payload时显式标记不可恢复，不能用空对象冒充有效快照 |
| `lab_monthly_snapshots` | 过渡期只保留每月当前有效结果；去掉历史修订浏览，最终可由日账及质量元数据生成 |
| `lab_runtime` | 复用为保留策略版本、迁移/维护游标和进度；不另起定时任务 |
| 输入/覆盖表 | 依赖清理并合并范围摘要；保留采集高水位与清理水位的区别，避免重查/seed反复写回已清历史 |

索引实施要点：

- 当前`lab_decisions_pending(status,issue_key)`把已结算行也放进索引。迁移改用明确`WHERE status='pending'`的部分索引，按全局与实验内pending查询的实际计划选择字段。
- 待终态迁移清理结束后，移除不再需要的`lab_decisions_finished(status,finalized_at)`，保留pending身份唯一约束。
- 停止按完成时间保留轮次后，移除相应旧轮次清理索引。
- 不盲目删除输入索引；先用`EXPLAIN QUERY PLAN`和基准验证分页、冻结版本读取及清理路径。SQLite部分索引的查询谓词必须能蕴含索引谓词。

参考：[SQLite partial indexes](https://www.sqlite.org/partialindex.html)。本次通过Context7核对了部分索引的建索引谓词与查询使用规则。

## 8. API与页面

沿用现有session/admin/owner、no-store、严格字段校验及16KB写请求限制。GET只读，不能因为展开存储面板就清理数据。

- 结果页重点展示参数、累计表现、风控效果、日/月曲线和组间差异。去掉历史逐笔、闭轮详情与历史月报修订选择器。
- 过渡期实验详情保留`recent: []`、`recent_rounds: []`兼容旧前端，同时新增`detail_policy: "results_only"`、`retention_version`、`pending_count`。不能把空数组显示成“实验没有投注”。
- 续算状态和分段接口保留必要进度/身份信息；已经清掉完整payload的段返回`checkpoint_retained: false`，不展示历史恢复入口。
- `/storage`说明“保留成绩与运行必需数据，不保留已结算逐笔明细”，分别展示实际目录字节、必要输入积压、待结算数、历史清理和物理回收进度。逐表归因由维护任务采样并附时间，GET不反复扫描百万行。
- 金额重测/修改并新建前显示可用日期范围。可在原实验的只读`replay-preview`返回`available / reason / requested_range / verified_range / input_basis`；提交时必须重新验证和保护，不能把预览当永久授权。
- 原区间缺输入时返回409 `replay_input_unavailable`；当时原本无预测与保留策略清掉的输入是不同情况。继续模拟旧成绩不需要该旧全区间，不能误禁正常增量续算。

不提供“保存全部逐笔”开关，不增加新的历史明细查询功能。

## 9. 容量模型与验收目标

改造后的主要增长应为：

`共享必要输入 + 版本数 × (配置与当前状态 + 回测天数 × 每日日结果) + 必要pending/检查点 + SQLite开销`

不再有`版本数 × 全部回测期数 × 逐笔记录及索引`这一项。不同止盈止损/熔断组合仍会增加计算时间，但不应各自增加整段逐期历史。

下面按**每版本配置/状态8KiB、每条日汇总含索引256字节**作保守规划示例，均不是已验证的实测上限，且不包含共享输入/WAL/备份：

| 参数版本数 | 60天日汇总 | 配置与当前状态 | 两项合计 |
| ---: | ---: | ---: | ---: |
| 600 | 8.8 MiB | 4.7 MiB | 13.5 MiB |
| 1,000 | 14.6 MiB | 7.8 MiB | 22.5 MiB |
| 10,000 | 146.5 MiB | 78.1 MiB | 224.6 MiB |

后两行仅说明增长模型，不代表本次把保存/运行上限改为这些数量。按1000版本观察一年，日汇总约89.1MiB；这是结果保留本身的预算，需要如实显示。

本次479MiB样本中约410MiB来自将被移除的逐笔及索引，减去必要pending后有明确的缩减空间。实施时须另取固定一致副本；以该479MiB量级数据为参考，迁移和实际回收后**总目录≤150MiB作为待验证验收目标**（本轮仅只读采样，未做副本清理实测）；若受保护输入导致不满足，必须列出实际字节及依赖，不能靠删必需数据达标，也不能宣称已经达到。

继续1GiB应用总预算、1核/256MiB。使用同一预算门禁计算常驻数据、WAL和瞬时开销，避免一个门禁按80%、另一个实际更早满但页面却声称还可用。物理空闲页与文件大小分别显示，不能把删除行数作为释放字节。

## 10. 安全迁移与物理回收

1. **冻结清理范围**：只允许清理已结算/跳过逐笔、无依赖闭轮和旧风险日、过期完整快照、无消费者输入/覆盖。配置、结果、pending、活动状态、去重水位、队列均在保护清单内。
2. **先用一致副本验证**：记录配置、累计stats、每日日账、运行状态、水位、pending、输入保护集合与队列摘要；把同一批输入在旧实现与结果型实现上跑完比较。
3. **先改变新增写入**：新结算完成即移除pending，不再继续制造终态历史；随后后台按持久化游标清旧数据。不能只清一次却继续按旧规则增长。
4. **短维护窗口切换**：依次暂停实验队列/worker/API；生成一份受控外置备份；迁移结构、补齐边界与必要统计；逐字段核对后恢复先前活跃服务和原进度。不重启上游，不重跑全部实验。
5. **后台有界清理**：每事务最多500行、持久化阶段/游标；每tick预留维护预算，不能只等回放结束后偶尔清500行；锁忙退让、崩溃可续。先清占比最大的终态逐笔，再清轮次、旧快照与无依赖输入。
6. **实际缩文件**：复用现有INCREMENTAL模式，每步至多256个freelist页并完整消费SQLite游标。WAL checkpoint忙则等待；文件减少与备份占用分别报告。
7. **副本和线上核对**：受保护字段、累计值/日账保持；两个正在跑的批次继续推进；只读UI无旧明细保留承诺。观察一轮新增数据，确认终态记录不再随处理期数增长。

备份不是另一套长期档案：实施迁移时只生成一份清单管理的回滚备份，验收后保留72小时并通过明确的维护命令按期限移除；不新增定时器、不顺带删除本次范围外备份。临时测试副本在验证结束后清理。空间报告必须同时列出数据库目录与此次外置备份，不能声称把空间问题转移出去就解决了。

清掉明细后不能靠恢复旧备份覆盖已经继续生成的新成绩。回退仅使用兼容结果型存储的代码，或停写后在副本验证恢复方案；保留迁移记录。

## 11. 必须通过的验收

| 场景 | 要求 |
| --- | --- |
| 条件×止盈×止损×熔断×冷却矩阵 | 旧/新实现输入相同，累计、日/月结果、最大回撤、最长连亏、轮/风控计数及游标一致 |
| 历史回放/实时/连续/比较组 | 全部运行路径都不写长期终态逐笔；比较组同输入同截止仍可比 |
| 单笔舍入和不同止盈路径 | 金额变化仍逐笔计算，不能以线性缩放替代 |
| 两笔重复结算、重复输入、旧revision、进程重启 | 每笔只计一次，删除已结算行后也不重复收益 |
| 提交前/提交后崩溃 | pending和结果的原子关系成立；无需读取已删除历史恢复 |
| 超过200笔迟到pending、跨日/月活动轮 | 所有必要pending保留，顺序结算，日风险/冷却/资金高点连续 |
| 已消费A清掉，追加B | 仅凭当前状态、暖机和B得到与一次跑A+B一致的结果 |
| 暂停或最慢比较子方案、原队列未启动 | 清理不删仍需输入；单个旧pending不把全部中间历史钉住 |
| 冻结方向被上游修订、pending状态后来完成 | 方向不能串版本；合法状态推进不被永远冻住 |
| 源清理后的重测 | 明确拒绝缺区间；原成绩和正常续算可用 |
| 日/月报与新增熔断指标 | 旧结果保持；未知旧指标显示未记录，不编造0 |
| 新创建/原地编辑/删除/幂等重试 | 现有管理、权限、容量、ID高水位与队列不回归 |
| 固定生产副本迁移与清理中断 | 允许删除范围之外的原值保持，恢复后可续；quick_check/FK通过 |
| 容量曲线 | 固定100/600版本跑不同长度，终态逐笔和闭轮行数保持0；只有结果日数及必要输入增长 |
| 性能/内存 | 1核/256MiB内完成；与当前优化版同输入比较耗时，原则上无超过10%的可解释外显回退 |
| 物理空间 | 固定副本记录DB/WAL/目录/备份真实字节，达到目标或明确未达原因；不以逻辑删除冒充缩文件 |

测试中的旧逐笔轨迹只能存在于测试临时目录，用于流式一致性断言；不得为了验证而给生产重新加长期逐笔日志。旧结构保持全表行数不变不再是验收标准，应精确区分“允许删除的冗余”与“绝对不可改变的结果和状态”。
